# F-10. Метки времени syslog, access-логов и nginx error

Статус: принят 18 ноября 2026, для `0.4.1`. Задача `F-10` из `docs/roadmap.md`. Время без даты вынесено в `F-11`, граница записи без слова уровня — в `F-12`.

## Задача и границы

Встроенные схемы Q-5 показывают поля syslog, access-логов и nginx error, но у записи нет момента: классификатор меток не понимает эти виды. Без момента не работают порядок слитой вкладки, фильтр времени, таймлайн и From/To сканера каталога.

Входит: `2026/11/18 13:55:36` (nginx error), `18/Nov/2026:13:55:36 +0000` (access nginx/Apache), `Nov 18 13:55:36` и `Nov  8 03:04:05` (syslog RFC 3164, без года).

Не входит: время без даты (`[13:55:36 INF]` Serilog console, `13:55:40.016 [main]` Logback) — `F-11`; названия месяцев не по-английски; RFC 5424.

## Как устроено сейчас

- **Один классификатор.** `LineClassifier` (`src/lineclassifier.cpp`) — ручной сканер, его зовут `LogParser` (вкладка, резидентный путь), `LogIndexer` (индексный путь) и `LogParser::analyzeFileForStats` (сканер каталога). Метку ищет ISO-сканер — самое левое `dddd-dd-dd[ T]dd:dd:dd` где угодно в строке; если её нет — фолбэк-формы `dd/MM/yyyy`, `MM/dd/yyyy`, `dd.MM.yyyy` только с позиции 0. За секундами любой формы — общие дробь и зона (`scanFractionAndZone`).
- **Эталон.** Ручной сканер обязан совпадать с регексами `PatternHeuristics::isoTimestampDetectPattern()`/`timestampSuffixDetectPattern()`: `testClassifierRegexEquivalence` в `tests/lineindex_smoke` — корпус и детерминированный фаззинг; семантика — `testTimestampGolden` против заранее известных моментов.
- **Первичная строка.** `isPrimaryLine`: строку распознала схема ИЛИ у неё есть и метка, и уровень. Момент записи берётся у классификатора и для строк, принятых схемой: поле схемы момента не задаёт. ISO-метка в середине строки с уровнем делает строку первичной — так было всегда.
- **Блок Timestamp схемы** строится из `PatternHeuristics::timestampRegex()`; им же пользуются автоопределение (`suggestSchema`) и токенизация двойного клика. Access и syslog в Q-5 описаны блоком `regex`: `timestampRegex` их не понимал.
- **Классификатор без состояния и без контекста файла**: строка → момент. Год ему взять неоткуда.

## Решение

### Формы

| Форма | Где в строке | Зона |
| --- | --- | --- |
| `yyyy/MM/dd HH:mm:ss` (и `T`) | как ISO: самая левая где угодно; разделители даты одинаковые | общая; nginx error пишет без зоны — локальное время |
| `dd/Mmm/yyyy:HH:mm:ss` | самая левая где угодно (у access-лога метка стоит после клиента) | общая; ` +0000` access-лога — существующая форма «через пробел». Не обязательна: без неё — локальное |
| `Mmm dd HH:mm:ss`, `Mmm  d …`, `Mmm d …` | только с позиции 0 | общая |

Месяцы — только английские сокращения `Jan`…`Dec`, регистр сворачивается для ASCII (как у слов уровней). Дробь любой длины усекается до миллисекунд, как у ISO.

**Где метка делает строку первичной.** Правило ISO сохраняется: формы с полной датой (у них есть год) ищутся по всей строке, как ISO, и, как ISO, делают строку первичной только вместе со словом уровня или схемой. Короткая форма syslog без года — только с начала строки, как фолбэк-формы: `at Nov 18 13:55:36 the job…` в тексте исключения записью не станет.

**Порядок.** Метка на позиции 0 любой формы главнее метки в середине: у строки syslog с ISO-датой в тексте сообщения момент — начало строки. Иначе берётся самая левая из «серединных» форм (ISO, `yyyy/MM/dd`, access). Найденная форма с невалидной датой — не метка, без отката к следующей (как у ISO сейчас). Прежнее поведение меняется только у строки, где фолбэк-форма стоит в начале, а ISO-метка — дальше: теперь момент — начало строки.

### Год для меток без года

Год — ближайший к опорной дате в прошлом: метка получает **последний год, в котором её день не позже следующего дня после опорной даты**. Опорная дата — локальная дата mtime файла. Сутки запаса — на чужой часовой пояс и часы писателя. 29 февраля в невисокосном году отступает к ближайшему високосному.

- Переход через Новый год внутри файла: mtime `2027-01-02`, строки `Dec 31 …` → 2026, `Jan  1 …` → 2027. Правило построчное, без состояния: оба бэкенда и сканер дают одно и то же, порядок файла не важен.
- Дозапись: каждая порция (`startParsingFrom`, `startIndexingFrom`, хвост сканера) берёт mtime заново. Строки `Jan 1`, дописанные после Нового года, получают новый год; уже прочитанные строки не пересчитываются — они свой момент получили по mtime той порции, и он был верным.
- stdin: спул — растущий файл, его mtime — время последней записи, то есть «сейчас».
- Цена суток запаса: у файла ровно на год, изменённого 31 декабря, строки 1 января уходят в следующий год. Обратная ошибка без запаса хуже и чаще: лог сервера в поясе восточнее зрителя потерял бы год у последних, самых интересных строк. Повторное чтение всего файла (F5 после перезаписи, переход вкладки на индексный бэкенд) берёт новый mtime; год строк при этом меняется, только если файл охватывает почти год.
- Файл, пролежавший больше года после последней записи, получает верный год (mtime старый), а файл, переписанный копированием без сохранения времени, — год копирования. Это граница способа, а не ошибка.

**Одна политика.** Правило живёт только в `LineClassifier`: он принимает опорную дату параметром (`YearReference`), а `yearReferenceForFile(path)` строит её из mtime. Читатели файла только передают её — сами год не считают. Без опорной даты (фильтр времени, Go to) — сегодняшняя дата.

### Блок Timestamp и схемы

`timestampRegex()` понимает access (вместе с ` ±hhmm`: зона внутри скобок) и syslog-форму. Автоопределение на строках access и syslog даёт блок Timestamp. Встроенные `access-combined` (поле `Time`) и `syslog-rfc3164` (поле `Timestamp`) переходят на блок `timestamp`; нетронутые установленные копии обновляются по манифесту (правило Q-5), это закреплено тестом на прежних версиях файлов.

## Отвергнутые варианты

- **Год по текущей дате.** Проще (без контекста файла), но архивный `syslog.1` прошлогодней ротации, открытый в январе, получил бы будущие даты, а годовалый — не тот год.
- **Год по состоянию разбора** (откат на год, когда метки пошли назад). Нужен перенос состояния через дозапись, через границы порций индексатора и в сканер; построчное правило по mtime даёт то же на любом файле короче года и без состояния.
- **Метки в середине строки для syslog-формы.** `Nov 18 13:55:36` в тексте сообщения — обычное дело (письма, стек-трейсы с датой сборки); без года отличить её нечем.
- **Время без даты сейчас.** Дата — догадка, а резидентная вкладка сортирует записи по моменту: консольный лог за несколько дней, сведённый к «последним суткам до mtime», перемешался бы по времени суток. Правильно — дата с переходом суток по состоянию разбора; это отдельная задача `F-11`.

## Проверки

- `lineindex_smoke`: регекс-эталон (`isoTimestampDetectPattern` с `/`, новые `accessTimestampDetectPattern`, `syslogTimestampDetectPattern`) против сканера — корпус, фаззинг со словами месяцев, искажения новых основ; эталон получает ту же опорную дату. Golden: зона access, переход суток и года, 29 февраля, сутки запаса, «похоже, но не метка» (`Nov 18 13:55` без секунд, `Foo 18 …`, метка syslog в середине, `31/Nov/2026`). Золотое сравнение `LogParser`/`LogIndexer` на файле новых форм, в том числе дозапись.
- `builtin_schemas`: `testClassifierTimeGap` перевёрнут — метки access, syslog, nginx error распознаются, Serilog console и время без даты — нет (`F-11`); оба бэкенда дают записям одни моменты; прежние версии двух схем, установленные нетронутыми, заменяются новыми.
- `dirscanner_smoke`: From/To у файла syslog и access.

## Цена

`lineindex_smoke --bench-stages`, 2 млн строк, Release, облачная машина (4 ядра), по три прогона; «до» — тот же бенч на коде до F-10. Стадия 2 (`detectTimestamp`, как у резидентного пути) почти целиком — построение `QDateTime` на строку, поэтому добавлена стадия 5: декод + `detectTimestampMs` с опорной датой файла — горячий путь индексатора.

| Лог | До, стадия 5 | После, стадия 5 |
| --- | --- | --- |
| генератор (ISO, 10 % многострочных) | 0,79–0,85 с | 0,75–0,82 с |
| access, зона `+0000` | 0,37–0,40 с (метки нет) | 0,20–0,22 с |
| syslog, одна минута на весь файл | — | 0,15 с (декод — 0,11 с) |
| syslog, минута меняется каждые 60 строк | 0,35–0,40 с (метки нет) | 1,3–1,45 с |

ISO не замедлился. Access дешевле, чем раньше без метки: форма находится рано, вместо прохода до конца строки, а момент с зоной считается арифметикой. Строка syslog проверяется с позиции 0 до прохода по строке. Последняя строка таблицы — не цена сканера: это прежний перевод локального времени в epoch раз на новую минуту (на этой машине ~35 мкс), его так же платит ISO; синтетический файл меняет минуту в 60 раз чаще настоящего лога со строкой в секунду.

## Риски

- Горячий путь: строка без ISO-метки в начале теперь проверяет ещё две формы. Проверки встроены в тот же проход по строке, а форма syslog — одна проверка позиции 0.
- Строка, у которой в середине `dd/Mmm/yyyy:hh:mm:ss` и слово уровня, становится первичной — так же, как с ISO-меткой.
- Зона через пробел со знаком (` -1000 balance`) остаётся известной неоднозначностью общей формы.
- Момент получает только ПЕРВИЧНАЯ строка, а без включённого Filter blocks первичная — с меткой и словом уровня. Строки access-лога (уровня нет) и syslog без слова уровня в этом режиме — продолжения первой записи, и момента у них нет. Это правило границ записей (Q-15) для всех логов, а не форма метки; задача `F-12`.
