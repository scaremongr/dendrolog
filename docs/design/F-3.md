# F-3. ANSI-последовательности

Статус: принят 26 ноября 2026. Задача `F-3` из `docs/roadmap.md` (0.7, дорожка A). Критерий: escape-коды не видны в тексте и не мешают поиску; цвет — по настройке.

## Задача и границы

Цветной вывод попадает в лог из `docker logs`, `kubectl logs`, вывода команды (F-7) — Spring Boot, Serilog console, pino-pretty, npm — и из файлов, куда записали цветную консоль: `\x1b[32m2026-11-26 10:00:00\x1b[0m \x1b[31mERROR\x1b[0m …`. Сейчас коды видны как мусор, `ERROR foo` не находит `\x1b[31mERROR\x1b[0m foo`, уровень и метка за кодом не узнаются.

Входит: снятие последовательностей на чтении (оба бэкенда, сканер), цвет SGR при отрисовке по настройке. Не входит: курсорные коды как действие (`\r`, `ESC[K`, `ESC[2J` и т. п. просто снимаются), состояние SGR через перевод строки, ссылки OSC 8 (снимаются, ссылкой не становятся), 8-битные C1 (0x9B как CSI): в UTF-8 это байт продолжения, в cp1251 — буква.

## Грамматика (ECMA-48), одна для байтов и для UTF-16

- **CSI** `ESC [` параметры 0x30–0x3F, промежуточные 0x20–0x2F, финальный 0x40–0x7E.
- **Строковые** `ESC ]` (OSC), `ESC P` (DCS), `ESC X`, `ESC ^`, `ESC _` — до BEL (0x07) или ST (`ESC \`).
- **nF** `ESC` промежуточные 0x20–0x2F финальный 0x30–0x7E (`ESC ( B` у `tput sgr0`).
- **Fe / Fp / Fs** `ESC` + 0x30–0x7E — два символа.
- **Оборванная** последовательность (конец строки или посторонний символ внутри — управляющий, `'\n'`, ≥ 0x80): снято то, что уже разобрано; посторонний символ остаётся текстом. Поэтому последовательность не переходит через `'\n'`, и снятие по блоку из нескольких строк (сканер) = снятие по каждой строке.
- **Одиночный ESC** (в конце строки или перед символом, не начинающим последовательность) — снимается один.

Модуль — `src/ansiescape.{h,cpp}` (ядро, рядом с `TextDecoder`).

## Решения

1. **Одна точка снятия — декодер.** `TextDecoder::decode` снимает последовательности из БАЙТОВ строки до декодирования; строка без 0x1B проверяется `memchr` и декодируется как прежде, без копии. Через декодер идут все читатели текста: индексатор, `TextChunkCache` (отображение индексной вкладки), `SequentialLineReader` (фильтр, поиск, статистика индексной), не-ASCII строки резидентного парсера, фильтр сканера (`FileContentSearch`). Остальные пути снимают сами той же функцией: ASCII-строка резидентного парсера (`fromLatin1`), UTF-16/32 (`QTextStream` — `AnsiEscape::stripInPlace(QString&)`), счётчики сканера (`analyzeFileForStats` — `QStringDecoder`), широкая ветка фильтра сканера. Отображение, быстрый поиск, Find All, Text Filters, подсветка, поля схем, Entry Details, копирование и Save View As видят один и тот же текст без кодов. Файл на диске не меняется; индекс хранит сырые смещения и длины (байтовая длина строки — оценка ширины, как и у UTF-8).
2. **Классификатор видит текст без кодов** на обоих путях: и парсер, и индексатор классифицируют уже декодированный (снятый) текст, `LineClassifier` не тронут. `\x1b[31mERROR\x1b[0m` — уровень, `\x1b[32m2026-…` — ведущая метка с позиции 0.
3. **ESC внутри многобайтного символа** снимается из байтов: `D0 1B[31m 9F` → `П`. Так же в cp1251 (однобайтная — тривиально). Автоопределение кодировки смотрит сырые байты: коды — ASCII и решения не меняют (кроме такого разрыва символа — пренебрежимо).
4. **Отпечаток строки (R-1) не учитывает последовательности** ни в тексте (`ofLineText`), ни в байтах (`ofLineBytes` снимает их до скелета): отпечатки бэкендов снова равны и равны отпечатку сырых байтов. Имя алгоритма (`sha1-64-ascii`) прежнее — иначе отказ получили бы все сохранённые места. Сохранённые до F-3 закладки, позиции и история **на строках с кодами** станут «строка не найдена» (их отпечаток считан с кодами); на прочих строках ничего не меняется.
5. **Цвет — только для отрисовки видимых строк.** `AnsiEscape::styles` разбирает SGR (0, 1, 2, 3, 4, 7, 22–24, 27, 30–37, 38;5;n, 38;2;r;g;b и формы через `:`, 39, 40–47, 48;…, 49, 90–97, 100–107) в спаны `AnsiSpan` в координатах ТЕКСТА без кодов. Каждая строка начинается со стиля по умолчанию: индексная вкладка читает строку отдельно, и бэкенды обязаны совпадать.
   - Резидентный: парсер считает спаны для строк с ESC (и только для них) и кладёт в запись (`LogEntry::ansiStyles`, указатель, `nullptr` у остальных). Цена — 8 байтов на запись (88 → 96); без этого цвет пришлось бы держать побочной таблицей с мьютексом или перечитывать файл без смещений строк.
   - Индексный: по требованию из сырых байтов строки (`TextChunkCache::lineBytes`, тот же кэш чанков), `memchr` у строки без ESC.
   - Роль модели `AnsiStyleRole` (`LogStore::ansiStylesAt`) — только когда показан сырой текст строки (а не выбранные колонки полей): иначе позиции не совпали бы. View спрашивает её только при включённой настройке; результат запекается в пиксмап строки.
6. **Палитра — `AppTheme::ansiColor(index, palette)`**: 16 цветов своих для светлой и тёмной темы (белый в светлой и чёрный в тёмной — читаемые серые), 216-кубик и серые — по xterm. Цвет текста, неотличимый от фона (контраст < 1,6), заменяется цветом текста палитры — в том числе truecolor.
7. **Сочетание с раскраской токенов:** спаны ANSI главнее, токены `SyntaxHighlighter` раскрашивают только промежутки между ними. Жирный — жирным начертанием (глифы ставятся по сетке колонок, ширина не меняется), курсив и подчёркивание — шрифтом, dim — смесь с фоном, inverse — обмен цветов. Выделение и подсветка совпадений рисуются поверх как прежде (совпадение перерисовывает текст контрастным цветом, начертание остаётся).
8. **Настройка** `[View] ansiColors` (`AppSettings::ansiColors`, по умолчанию включено): Settings → Appearance и `View → ANSI Colors`. Выключено — коды всё равно сняты, строка раскрашивается обычными токенами.

## Ловушки

- Предпросмотр дат времени без даты (`LineClassifier::clockRunInFile`, F-11) читает голову строки сырыми байтами: `\x1b[2m13:55:36` он не видит, а проход видит. На логе консоли, где перед временем стоит код, дни считаются от mtime без переходов через полночь. Задача S-25 (правка внутри классификатора — после F-17, шаг 2).
- Состояние SGR через строки не переносится (многострочный цветной блок с одним сбросом в конце покрашен только в первой строке).
- `Show Full Text` и Entry Details показывают текст без кодов; цвета там нет.

## Цена

Замер 26 ноября 2026, облачная машина (4 ядра, шум между прогонами ±15 %), `scripts/generate_test_log.py --size 300M` (3,4 млн строк) и тот же лог, раскрашенный как консоль Spring Boot (метка — `ESC[2m`, уровень — свой цвет, продолжения — `ESC[90m`; 367 МБ).

- **Без кодов** — в пределах шума. Медианы шести чередующихся прогонов `main` / F-3: `--bench` 1,86 / 1,99 с, `--bench-resident` 4,48 / 4,85 с — разброс самих прогонов шире разницы. Чистая цена — стадия 6 `--bench-stages` (только декодирование, минимум из пяти): 0,268 → 0,278 с, ≈ 3 нс на строку (`memchr` по байтам строки), ≈ 0,5 % индексации.
- **С кодами** (F-3, тот же файл раскрашенный против бесцветного, по четыре прогона): индексация 1,57–2,03 → 1,92–2,27 с (+15 %, файл на 17 % длиннее), резидентный разбор 4,5–5,3 → 6,1–6,6 с (+30 %: снятие, спаны SGR и их хранение у каждой строки), стадия 6 — 0,28 → 0,57 с (снятие ≈ 85 нс на строку). Записей и уровней — столько же, сколько у бесцветного.
- Память резидентной вкладки: +8 байтов на строку (указатель стиля в `LogEntry`); у строк с цветом — ещё спаны (24 байта на спан и заголовок вектора).
