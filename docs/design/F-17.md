# F-17. Log Fields без настройки: проверка на файле, подбор схемы, нейро-подсказчик, редактор от примера

Статус: спроектирован 26 ноября 2026 по слову автора («хорошо продумай и напиши подробный план по новому Log Fields; нейронный подсказчик — в план пораньше; профиль под тип лога — эвристика при открытии файла»). Код читался на `43e04f7`: F-4 готов целиком (ключевые схемы, режим JSON / logfmt в редакторе, `suggestKeyedSchema`), F-5 — PR 1 и PR 2 готовы (схема на вкладку, `FieldSchemaController`, `fieldlayout`), PR 3 (схема на файл) впереди. Задача `F-6` («предложение схемы при открытии») входит сюда шагом 5.

## Задача и границы

Жалоба автора: интерфейс Log Fields громоздкий и непонятный, правила разбиения сложные; хочется режим, который сам правильно разбивает строки по нескольким десяткам образцов — нейросетью или иначе.

Цель в трёх фразах:

1. Открыл лог знакомого формата — поля уже есть, ничего не нажимая.
2. Открыл незнакомый — одна кнопка даёт разбиение, а программа честно говорит, сколько строк файла оно разобрало и какие не подошли.
3. Правка разбиения — это правка на настоящих строках (выделил кусок — стал полем), а не сборка парсера из блоков.

Входит:

- мера «насколько схема подходит файлу» и подбор схемы из каталога по ней;
- нейро-подсказчик схемы (по желанию, выключен по умолчанию);
- вывод структуры по строкам алгоритмом, без сети;
- док Log Fields: выбранная схема работает сразу, «Filter blocks» уходит;
- подбор схемы при открытии файла (бывшая F-6);
- новый редактор: таблица образцов, правка на строке, одно сохранение.

Не входит: новый движок разбора и новый формат файла схемы (`LogPattern`, каскад регексов, версия формата 3 — без изменений; каждая существующая схема открывается и работает как раньше), табличный режим строк во view (U-18), несколько схем на один файл, разбор структуры внутри сообщения, анализ содержимого лога нейросетью.

## Как устроено сейчас

- **Схема инертна, пока не включена галочка «Filter blocks».** `FieldSettings::extraction` (`src/documentstate.h`) — одновременно «извлекать поля» и «показывать только выбранные блоки». Выбрал схему, галочку не тронул — нет ни полей в фильтрах, ни границ записей по схеме (`CLAUDE.md`: «только при включённом извлечении полей»). Включил — меняется и сам текст строки. Название «Filter blocks» при этом читается как фильтр строк.
- **Редактор — конструктор парсера.** `ConversionPatternDialog` (1776 строк): слева таблица схем, справа цепочка карточек `PatternBlockCard`. У блока 11 типов (`PatternBlock::MatchKind`), отдельно обёртки («Enclosed by»), отдельно разделитель до следующего блока (`SeparatorNode`: авто / текст / регекс), галочка hide. Выбор между «Text», «Greedy text» и «Remainder» требует знать каскад «полный регекс → префиксы → re-sync».
- **Правка и результат разнесены:** карточки сверху, образцы строк внизу, связь — цвет. Образцов из файла окно передаёт восемь (`MainWindow::onManagePatterns`), остальное пользователь вставляет руками.
- **«✨ Suggest schema» смотрит на одну строку** (`PatternHeuristics::suggestSchema(const QString&)`): слева направо, первое свободное слово — «Source», первая скобка — «Thread», дальше — «Message». Для JSON / logfmt уже есть подбор по нескольким строкам (`suggestKeyedSchema`).
- **Нет меры качества.** Подпись «Schema is valid» говорит только, что определение синтаксически верно. Сколько строк файла схема разбирает, не знает никто, пока пользователь не пролистает лог.
- **Три похожих понятия и два сохранения:** схемы (файлы `patterns/*.json`), пресеты (ini и `builtInPresets()`), встроенные схемы; Apply / Revert для правок и отдельно Use Selected. Диалог модальный — лог за ним не посмотреть.
- **Новая вкладка получает схему по умолчанию** — последнюю выбранную в доке (F-5, PR 1), какой бы файл в ней ни открыли.
- **Что хорошо и остаётся:** движок с мягкой деградацией (строка, отклонившаяся от схемы, не теряет поля), `matchLine` = то, что делает парсер; предпросмотр считается в воркере со сторожем от тяжёлого регекса; встроенные схемы по манифесту; ключевые схемы.

## Что увидит пользователь

**Знакомый формат.** Открыл `app.log` из Spring Boot. В строке статуса на несколько секунд: «Schema: Spring Boot (auto)». Текст строк прежний; в Text Filters доступны правила по полям `Level`, `Logger`, `Thread`, в Entry Details — поля записи, стек-трейсы лежат в своих записях. В доке Log Fields: `Spring Boot · auto`, ниже «Parsed 99.6% · 3 lines did not match».

**Незнакомый формат.** Схема не подобрана, док показывает «No schema» и кнопку **Find a Schema**. Нажал — открылся редактор со списком вариантов: «From sample lines — 6 fields, parsed 98%», «From sample lines (short) — 4 fields, 100%», при включённом подсказчике — «AI — 7 fields, 99%». Щелчок по варианту показывает его в таблице образцов; **Use** делает его рабочим. Имена полей правятся двойным щелчком по заголовку.

**Правка.** В таблице образцов колонка `Message` начинается с `[req-4f2a]`. Выделил `req-4f2a` мышью в одной строке, нажал **Make Field** — появилась колонка между `Logger` и `Message`, значение выделено во всех образцах; подпись: «New field found in 47 of 50 samples». Не то — `Ctrl+Z` или **Other Variant**.

## Решение

### 1. Мера соответствия: `SchemaFit`

Новый модуль ядра `src/schemafit.*`. Одна функция отвечает на вопрос «сколько строк разбирает схема», ею пользуются подбор из каталога, вывод структуры, нейро-подсказчик, подбор при открытии, док и редактор — вторая мера нигде не заводится.

```cpp
namespace SchemaFit {
struct Miss {            // строка-кандидат, которую схема не приняла или приняла частично
    qint64  line;        // номер физической строки файла, 0 — образец без файла
    QString text;
    int     afterBlock;  // последний сошедшийся блок, -1 — ни одного
    int     stopOffset;  // где разбор остановился
};
struct Result {
    int examined   = 0;  // непустых строк
    int candidates = 0;  // похожих на начало записи (правило ниже)
    int full       = 0;  // кандидат, сошлись все блоки
    int partial    = 0;  // кандидат, принят деградацией (префикс или re-sync)
    int missed     = 0;  // кандидат, не принят
    int loose      = 0;  // принята строка, которая не кандидат
    QVector<int>  filled;   // по колонке: в скольких принятых строках поле не пусто
    QVector<Miss> misses;   // не больше 50
    bool timedOut  = false;
    double coverage() const;     // (full + 0.5 * partial) / candidates
    double specificity() const;  // среднее число непустых полей, кроме хвостового, на принятую строку
};
Result evaluate(const LogPattern& schema, const QStringList& lines, const Budget& budget = {});
}
```

- **Кандидат** — строка, которая начинает запись по правилу БЕЗ схемы: `LineClassifier::isPrimaryLine(false, …)` (F-12), время без даты читается с контекстом (F-11), иначе Serilog console не дал бы кандидатов. Если кандидатов меньше 20 % непустых строк (лог без меток: `WARNING:root:…`, JSON с эпохой числом) — кандидатами считаются все непустые строки без ведущего пробела и табуляции. Правило построчное, порядок строк не нужен.
- **Почему не «доля всех строк»:** продолжения записи (стек-трейс) схема и не должна принимать; считать их промахами — значит наказывать правильную схему.
- **`loose`** ловит слишком мягкую схему: один блок `Message` принимает всё и дал бы покрытие 100 %. Поэтому сравнивают по паре: покрытие, затем `specificity`; схема со `specificity` < 1 автоматически не выбирается никогда.
- **Порядок сравнения кандидатов** (`SchemaFit::better`): покрытие, округлённое до 0,02; затем `specificity`; затем меньше `partial`; затем порядок каталога.
- **Пороги** — константы в `schemafit.h`: «подходит» — покрытие ≥ 0,90 и `specificity` ≥ 2 (для ключевой схемы — ключ времени или уровня найден в ≥ 90 % принятых строк); «сомнительно» — 0,50…0,90; ниже — «не подходит».
- **Причина промаха** — данными, а не текстом: `explain(definition, matchResult)` → «после поля N ожидался литерал / число / метка, в строке — такой-то текст». Слова подставляет интерфейс («After Level a “[” was expected, the line has “-”»).
- **Бюджет:** проверка времени каждые 32 строки; превышен (по умолчанию 150 мс на схему) — `timedOut`, результат не используется. Защищает от тяжёлого пользовательского регекса там, где раньше защищал только сторож предпросмотра.
- **`SchemaFitJob`** — проверка на файле в пуле: снапшот всех строк вкладки (`LogStore::scanSnapshot(false)`), строки одного файла — первые 300 и 2000 равномерно по файлу, текст через `LineCursor` снапшота (индексный бэкенд читает диск в воркере, кэш вьюпорта не трогается). Поколение и флаг отмены, результат — `QFutureWatcher` на GUI-потоке, reset модели отбрасывает идущий расчёт. На GUI-потоке — O(1) на батч (инвариант 3): задание запускается по требованию (док виден, редактор открыт), а не на вставку строк.

### 2. Подбор из каталога

`SchemaFit::rank(schemas, lines)` — все схемы каталога по одним строкам, лучшая первой; схема с `timedOut` — в конец с пометкой. Это ступень «узнать знакомый формат»: дёшево, офлайн, без догадок — каждая встроенная схема проверена на настоящих строках (`tests/builtin_schemas`).

### 3. Нейро-подсказчик

Модель не разбирает лог. Она получает несколько десятков строк и возвращает **схему** в формате программы; разбирает по-прежнему `LogPattern`, а предложение проверяется тем же `SchemaFit` на настоящих строках. Ошибиться незаметно подсказчик не может: рядом с вариантом стоит число, а не подошедшие строки видны.

**Почему это несложно и стоит рано.** Всё трудное — проверка и показ варианта — общее с алгоритмом и делается шагом 1. Сам подсказчик — один HTTP-запрос, строгая проверка ответа и окно согласия. Сеть в программе уже есть (`UpdateChecker`, Qt Network в `dendrolog_app`). Встраивать модель в программу не будем: это сотни мегабайт и зависимость от рантайма, а маленькая локальная модель справится хуже алгоритма шага 3.

**Где сильнее алгоритма:** осмысленные имена полей (`RequestId`, `DurationMs`, а не `Field3`), необычные самодельные форматы, регекс для поля сложной формы. Где слабее: стоит денег и секунд, требует сети и согласия на отправку строк.

**Части:**

| Модуль | Цель сборки | Что делает |
| --- | --- | --- |
| `src/schemaproposal.*` | `dendrolog_core` | Текст запроса из строк (`buildRequest`), маскировка (`maskLine`), разбор и строгая проверка ответа (`parseResponse` → `PatternDefinition` или ошибка), текст уточняющего запроса. Без сети — проверяется обычным тестом |
| `src/aischemaclient.*` | `dendrolog_app` | Запрос через `QNetworkAccessManager`, отмена, тайм-аут 180 с, повторы; провайдер — интерфейс, первая реализация — Claude API; шов для тестов — адрес сервера параметром |
| `src/secretstore.*` | `dendrolog_app` | Хранение ключа вне ini |
| Settings → AI, окно согласия, пункт «Ask AI…» | `dendrolog_app` | Интерфейс |

**Запрос (Claude API, Messages).** Официального SDK для C++ нет, поэтому сырой HTTP:

```text
POST https://api.anthropic.com/v1/messages
content-type: application/json
x-api-key: <ключ пользователя>
anthropic-version: 2026-10-21
anthropic-beta: server-side-fallback-2026-07-01

{
  "model": "claude-opus-5-5",
  "max_tokens": 16000,
  "fallbacks": "default",
  "system": "<инструкция: модель блоков, правила, два примера>",
  "messages": [{"role": "user", "content": "<строки-образцы>"}],
  "output_config": {
    "effort": "medium",
    "format": {"type": "json_schema", "schema": { … }}
  }
}
```

- Модель по умолчанию — `claude-opus-5-5`; в настройках это строка, пользователь может вписать другую. Параметр `thinking` не передаётся (у этой модели размышление включено всегда), глубина — `output_config.effort`, задаётся явно.
- `output_config.format` с JSON-схемой: ответ — гарантированно разбираемый JSON нужной формы. Ограничения схемы API: у каждого объекта `additionalProperties: false`, все свойства в `required`, без числовых и строковых ограничений — длины и количества проверяет программа.
- `fallbacks: "default"` с бета-заголовком: строки лога (например, из журнала безопасности) может отклонить классификатор; сервер тогда сам повторит запрос на запасной модели.
- Ответ: первый блок `content[]` с `type == "text"` — JSON. До чтения проверить `stop_reason`: `refusal` — «модель отклонила запрос» (без повтора), `max_tokens` — ошибка «ответ оборван».
- Ошибки HTTP: 401 — «ключ не принят»; 429, 529 и 5xx — до двух повторов с паузой (`retry-after`; заголовок `x-should-retry: false` повтор запрещает); остальные 4xx — текст ошибки сервера без повтора. Отмена пользователем — в любой момент.
- Цена — по оценке 5–15 центов за запрос на модели по умолчанию (около 4 тыс. токенов на вход и несколько тысяч на выход вместе с размышлением); окно согласия показывает число строк и символов.

**Форма ответа** повторяет файл схемы, чтобы не заводить второй формат:

```json
{"format": "blocks" | "json" | "logfmt",
 "blocks": [{"name": "…", "kind": "timestamp|level|text|greedy-text|integer|hex|ip|path|constant|regex|remainder",
             "leadingText": "", "closingText": "", "separator": "", "separatorIsRegex": false,
             "customRegex": "", "hidden": false}],
 "timeKeys": [], "levelKeys": [], "messageKeys": [], "extraColumns": [],
 "comment": "…"}
```

Имена `kind` — те же, что пишет `LogPattern::serializeDefinition`. Для `json` / `logfmt` блоки пусты, заполнены ключи (`KeyedDefinition`).

**Проверка ответа (ответ модели — данные, а не доверенный ввод):**

1. Разбор JSON; неизвестный `kind`, больше 24 блоков, имя длиннее 40 символов или с управляющими символами — отказ.
2. `LogPattern::validateDefinition`; ровно один `remainder` и он последний (если модель забыла — добавляется `Message`).
3. Компиляция и `SchemaFit::evaluate` на ИСХОДНЫХ (не маскированных) образцах с бюджетом времени: `timedOut` — отказ «схема слишком медленная» (защита от катастрофического регекса).
4. Покрытие ниже 0,90 и есть промахи — один уточняющий запрос: прежняя схема и до 10 не подошедших строк. Второго уточнения нет.
5. Результат — вариант «AI» с числами рядом с остальными. Ничего не применяется само.

**Согласие и приватность:**

- Подсказчик выключен по умолчанию: Settings → AI → «Enable AI schema suggestions», провайдер, модель, ключ.
- Перед КАЖДОЙ отправкой — окно: куда уходит запрос (имя хоста), сколько строк и символов, точный текст в поле только для чтения. Галочки: «Mask values» (включена) и «Cut lines to 300 characters» (включена). Кнопки Send / Cancel. Уточняющий запрос показывает свои строки таким же окном. Галочки «больше не спрашивать» нет.
- Маскировка сохраняет форму и убирает значения: метки времени и слова уровней не трогаются (по ним модель узнаёт структуру), в остальном тексте каждая цифра заменяется на `0`, шестнадцатеричные серии от 8 символов — на `a` той же длины, адреса почты — на `user@example.com`, IP — на адрес из документационного диапазона. Слова остаются: без них не понять имя логгера и границу сообщения. Обрезка до 300 символов убирает большую часть текста сообщений. В окне сказано прямо: маскировка уменьшает, а не исключает утечку — отправляется ровно показанный текст.
- В запрос не попадают имя и путь файла, имя пользователя и машины. `User-Agent` — `DendroLog/<версия>`.
- **Ключ:** переменная окружения `ANTHROPIC_API_KEY`, если задана (поле в настройках тогда показывает «from environment»); иначе — введённый в настройках. В `DendroLog.ini`, сессиях, памяти файлов и трассировках ключа нет никогда. Windows — DPAPI (`CryptProtectData`, привязан к пользователю Windows; копия переносимой папки ключ не раскрывает), файл `<configDir>/ai-key.dat`. Linux — файл с правами 0600 только в непереносимом каталоге настроек; в portable-режиме на Linux ключ не сохраняется (только переменная окружения).
- Тела запросов и ответов не пишутся ни в какие логи.

**Инструкция модели** (файл ресурсов `resources/ai/schema-prompt.txt`, эталон в тесте): модель блоков в десять строк (виды, обёртки, разделитель, «последний блок — остаток»), правила («поле — только то, что есть в подавляющем большинстве строк», «не дробить свободный текст сообщения», «имена — `Timestamp`, `Level`, `Message` и осмысленные для остальных», «строки JSON или logfmt — вернуть ключи, а не блоки»), два примера «строки → ответ» (Logback и access-лог).

**Где появляется:** шаг 2 ставит пункт «Ask AI…» в меню кнопки «✨ Suggest schema» СУЩЕСТВУЮЩЕГО редактора — подсказчик полезен сразу, не дожидаясь нового; новый редактор (шаг 6) показывает тот же вариант в общем списке.

### 4. Вывод структуры по строкам: `SchemaInference`

Новый модуль ядра `src/schemainference.*`: до 200 строк → до трёх вариантов схемы, каждый с `SchemaFit::Result`. Детерминированно, без сети, за миллисекунды. Так устроены определители структуры в системах сбора логов; нейросеть для этого не нужна.

1. **Формат.** Большинство строк — JSON-объект или logfmt (`detectLineFormat`) — вариант от `suggestKeyedSchema`, дальше шаги не идут.
2. **Отбор.** Только строки-кандидаты (правило `SchemaFit`): продолжения записей ломают выравнивание.
3. **Токены.** Строка режется на типизированные куски с позициями: метка времени, уровень, IP, UUID, hex, число, число с единицей (`12ms`), путь, строка в кавычках, группа в скобках (`[…]`, `(…)`, `<…>`, содержимое классифицируется так же), `key=value`, слово, серия знаков-разделителей, пробелы. Формы — из `PatternHeuristics` (единственное место правил «как выглядит метка, уровень, IP»).
4. **Якоря.** Литералы-разделители из нескольких знаков (` - `, `: `, ` --- `, `]: `, ` | `), которые есть в ≥ 95 % строк в одном порядке, делят строку на отрезки. Это решает главную трудность — значения из нескольких слов без скобок: отрезок между якорями, где число токенов гуляет, становится одним текстовым полем «до якоря».
5. **Выравнивание.** Внутри отрезка слева направо: позиция — колонка, пока ≥ 85 % строк согласны в типе токена. Токен есть в части строк (от 15 до 85 %) — необязательное поле (текст, допускающий пустое значение). Согласие распалось — остаток строки `Message`. Строки делятся на две устойчивые группы с разным началом — берётся большая, вторая попадает в заметку «в файле два вида строк: 83 % и 15 %».
6. **Типы и имена** — по статистике колонки: метка → `Timestamp`; слова словаря уровней → `Level`; текст в скобках с малым числом разных значений сразу за меткой или уровнем → `Thread`; имена через точку (`com.example.App`) → `Logger`; постоянное или почти постоянное число → `Pid`; UUID и длинный hex с большим числом значений → `Id`; IP → `Ip`; одно и то же слово во всех строках после syslog-метки → `Host`; `слово[число]:` → `Process` и `Pid`; постоянный литерал — безымянная константа (структура строки, не поле). Остальные — `Field1`, `Field2`: переименовать проще, чем разметить.
7. **Варианты:** (а) полный заголовок; (б) осторожный — до первой необязательной или спорной колонки; (в) прежний `suggestSchema` по первой строке — чтобы результат никогда не был хуже сегодняшнего. Каждый проходит `validateDefinition`, компилируется и оценивается на всех строках; покрытие < 0,60 — отбрасывается. Порядок — `SchemaFit::better`.

### 5. Схема работает, когда выбрана (док Log Fields)

- `FieldSettings` получает `showFields` — «показывать в строке только выбранные поля». Наличие схемы само означает извлечение: поля в Text Filters и Search, Entry Details, экспорт, границы записей по схеме, время и уровень из ключей.
- Совместимость хранения — без роста версий: писатель по-прежнему пишет `extraction` (равно `showFields` — 0.7 прочитает как раньше) и новый необязательный `showFields`; читатель: `showFields` нет — берётся прежний `extraction`. Схема со старым `extraction: false` становится действующей, текст строк не меняется. ini `[View] fieldFilterEnabled` читается так же, новый ключ — `fieldShowSelected`.
- **Док:**

  ```text
  Schema: [ Spring Boot · auto        ▾ ]  [Edit…]  [⋯]
  Parsed 99.6% · 3 lines did not match
  Show in the log:  (•) Whole line   ( ) Selected fields
     [x] Timestamp  [x] Level  [ ] Thread  [x] Logger  [x] Message
  ```

  Список схем при открытии показывает покрытие текущей вкладки у каждой и ставит подходящие первыми. Меню «⋯»: Detect for This Tab, Apply Schema to All Tabs, Find a Schema…, Manage Schemas…. Строка покрытия — щелчок открывает редактор на списке не подошедших строк. Слова «block» в интерфейсе больше нет: везде «field».
- Цена: схема, выбранная без галочки, раньше не стоила ничего, теперь — разбор при загрузке. Отказ — пункт «No schema». Замер — в шаге 1 (`lineindex_smoke --bench` и `--bench-resident` со схемой), числа — в этот документ.

### 6. Подбор схемы при открытии файла (бывшая F-6)

Одобренный автором «профиль под тип лога»: эвристика при открытии подставляет нужную схему. Подставляется `FieldSettings` целиком (схема, `showFields = false`, все колонки) — вид строк не меняется, поэтому молчаливая подстановка безопасна.

Порядок для первого файла новой вкладки:

1. Есть сохранённое состояние (память файла, сессия, `Ctrl+Shift+T`) — оно, подбора нет.
2. **Имя.** Пользователь раньше выбрал схему для файла с таким именем — она, если её покрытие на начале файла ≥ 0,50. Ключ имени — имя файла в нижнем регистре без хвоста ротации (то же правило, что `scannerNameMatches`), серии цифр заменены на `#`: `app-2026-11-18.log.3` и `app-2026-11-19.log` дают один ключ. Таблица — ini `[SchemaByName]`, до 200 записей, свежие вытесняют старые; запись появляется, когда пользователь сам выбирает схему в доке.
3. **Содержимое.** `SchemaFit::rank` по началу файла; лучшая схема подставляется, если она «подходит» (пороги из раздела 1).
4. Иначе — схема по умолчанию (последняя выбранная в доке), если её покрытие ≥ 0,50; иначе вкладка без схемы, а док предлагает **Find a Schema**.

Механика:

- **До начала разбора.** Схема — параметр прохода парсера и индексатора (F-5, PR 2), ключевая схема меняет метки и границы записей; подобрать после загрузки значило бы перечитать файл. Поэтому `LogViewWidget::addLogFile` сначала запускает в пуле пробу `SchemaProbe`: до 256 КБ начала файла, декодирование тем же правилом, что у загрузки (BOM, `EncodingDetector`), до 400 строк, `rank` по копиям схем каталога (их даёт контроллер). Общий бюджет пробы — 300 мс; не уложившиеся схемы пропускаются. Обычно это единицы миллисекунд.
- **Мало строк** (растущий лог, stdin, меньше 20 непустых строк) — разбор стартует со схемой по умолчанию, одна поздняя проба — когда во вкладке 50 строк; смена схемы на маленькой вкладке дешева.
- **Сжатый файл и член архива** (F-2) — проба по распакованной копии, после распаковки.
- **Большой файл** (выше порога индексного бэкенда) и регексная схема: если замер шага 1 покажет замедление индексации больше чем в полтора раза — схема не подставляется молча, а предлагается плашкой над логом («Looks like Logback — Apply») с пометкой о времени. Ключевые схемы подставляются всегда: они почти бесплатны (×1,00–1,07, F-4).
- **Сообщение:** строка статуса «Schema: X (auto)» и пометка `auto` в доке; плашки над логом нет — на каждый открытый файл она была бы шумом.
- **Отказ:** выбрал другую схему или «No schema» — запоминается памятью файла (F-5) и таблицей имён; на этом файле и на файлах с тем же именем подбор больше не спорит.
- **Настройка:** Settings → General → «Pick a field schema automatically when a log is opened», включена.
- После F-5, PR 3 проба идёт на каждый файл слитой вкладки; до него — на первый файл вкладки.

Набор «схема + фильтры + подсветка» одним профилем не делаем: профили Text Filters уже есть, а подстановка фильтров без спроса прячет строки (решение R-4: фильтры предлагаются, а не применяются).

### 7. Редактор от примера: `SchemaEditorWindow`

Немодальное окно (одно на программу), заменяет `ConversionPatternDialog`. Работает с рабочей копией выбранной схемы; движок и формат файла прежние.

```text
┌ Schemas ───────────┬ Name [Spring Boot      ]  Format [Fields ▾]   [Find a Schema]      ┐
│ ✓ Spring Boot  99% │ Description [                                                    ] │
│   Logback      61% ├────────────────────────────────────────────────────────────────────┤
│   Syslog        0% │ Timestamp          │ Level │ Pid   │ [Thread] │ Logger     │ Message │
│   …                │ 2026-11-18T13:55…Z │ INFO  │ 34786 │ main     │ o.s.b.App  │ Started │
│ [New ▾] [⋯]        │ 2026-11-18T13:55…Z │ WARN  │ 34786 │ exec-1   │ c.e.Db     │ Slow q… │
│                    │ …                                                                   │
│                    ├ Did not match (3) ─────────────────────────────────────────────────┤
│                    │ 4812  ---- restart ----      no timestamp, level or fixed text      │
│                    ├────────────────────────────────────────────────────────────────────┤
│                    │ In the file: parsed 99.6% of 2,300 checked lines · 3 did not match  │
│                    │ ▸ Advanced: block chain                                             │
└────────────────────┴──────────────── [Apply to Tab]  [Save]  [Save As…]  [Close] ───────┘
```

- **Таблица образцов** (`SchemaSampleModel`): строка — образец, колонка — блок схемы. Ячейки — из `LogPattern::matchLine` (`BlockSpan`), то есть ровно то, что сделает парсер. Обёртки и разделители — приглушённым текстом в заголовке и ячейке (`[Thread]`), безымянные константы — узкие серые колонки. Скрытое поле — заголовок с перечёркнутым глазом. Хвост деградировавшей строки — в последней колонке с отметкой. Образцы: до 50 строк-кандидатов с текущего места вкладки и равномерно по файлу (то же задание, что у `SchemaFitJob`); «Add Samples» — из буфера обмена или файла, когда вкладки нет.
- **Не подошедшие** — отдельный список под таблицей: номер строки, текст, причина словами (`SchemaFit::explain`); двойной щелчок добавляет строку в образцы.
- **Строка покрытия** — `SchemaFitJob` по файлу вкладки, перезапуск через 400 мс после правки.
- **Типы для пользователя:**

  | В интерфейсе | `MatchKind` | Как выбирается |
  | --- | --- | --- |
  | Time | `Timestamp` | — |
  | Level | `Level` | — |
  | Value | `Integer`, `HexText`, `IpAddress`, `FilePath` или `TextUntilSeparator` | по значениям образцов; значок «number», «IP», … в заголовке |
  | Text | `TextUntilSeparator` или `GreedyTextUntilSeparator` | жадный — если в образцах разделитель встречается внутри значения |
  | Message | `Remainder` | всегда есть и всегда последний; удалить нельзя |
  | Advanced: Fixed text, Regex | `ConstantText`, `CustomRegex` | вручную |

- **Правка на строке:**
  - **Make Field** — выделение внутри ячейки. Гипотезы, где граница в остальных строках: (1) по разделителям — знаки сразу перед выделением и сразу за ним становятся обёртками или разделителем нового поля; (2) по номеру слова; (3) по типу — выделение целиком число, IP, hex, метка или уровень. Каждая гипотеза — определение-кандидат, оценивается `SchemaFit` на образцах; берётся лучшая, остальные — по кнопке **Other Variant**. Подпись — «New field found in N of M samples».
  - **Merge with Next** — два соседних поля в одно текстовое.
  - Заголовок: двойной щелчок — имя; меню — тип, Hide, Merge, Remove (поле уходит в соседнее справа).
  - `QUndoStack` на все правки (`Ctrl+Z` / `Ctrl+Y`); у нынешнего редактора отмены нет.
- **Find a Schema** — панель вариантов: лучшие из каталога (раздел 2), варианты вывода структуры (раздел 4), «AI» (раздел 3, если включён; иначе пункт «Ask AI… (set up)» ведёт в настройки). Щелчок — предпросмотр в таблице, **Use** — в рабочую копию.
- **Формат** Fields / JSON / logfmt — карточка ключевой схемы из F-4 остаётся; таблица образцов для неё та же (колонка — ключ), «Add keys from sample» — как сейчас.
- **Advanced: block chain** — нынешняя цепочка карточек (`PatternBlockCard`, `SeparatorNode`) без изменений, свёрнута по умолчанию. Вся прежняя мощь остаётся, таблица и цепочка правят одну рабочую копию.
- **Одно сохранение:** Apply to Tab (рабочая копия — на вкладку дока, в каталог не пишет), Save, Save As…; закрытие с несохранёнными правками спрашивает. Apply / Revert и Use Selected уходят.
- **Пресеты** сливаются со схемами: New ▾ → Empty, From Sample Lines, From Template (бывшие встроенные пресеты), Import Grok…, Import File…; пользовательские пресеты из ini один раз переносятся в каталог файлами, кнопка Save as preset уходит (есть Save As).
- Каталог пишет по-прежнему `FieldSchemaController::replaceCatalogue` → `SchemaStore` (описание и неизвестные ключи файла сохраняются, встроенные обновляются по манифесту).

## Проверки

- **Эталон — настоящие строки с заданным ответом**, а не второй разборщик: корпуса `schema_fit` и `schema_inference` — файлы строк и ожидаемые поля руками. Корпус встроенных форматов берётся из образцов `tests/builtin_schemas`, чтобы не разойтись с ними.
- **Одна мера.** Тест `schema_fit` закрепляет, что док, редактор, подбор и подсказчик зовут `SchemaFit::evaluate`, а не считают по-своему: счётчики окна на фикстуре равны счётчикам функции.
- **Оба бэкенда.** `SchemaFitJob` и подбор при открытии проверяются на резидентной и индексной вкладке (`testdocuments.h`); подстановка схемы до разбора не добавляет проходов — счётчики запусков парсера и индексатора.
- **Подсказчик без сети.** Весь путь — на локальном сервере теста; настоящий API в CI не вызывается. Ответ модели проверяется как недоверенные данные: таблица враждебных ответов в `schema_proposal`.
- **Ожидание состояния, не времени** (P-6, P-10): задания и окно — `waitFor` / `settleIdle`; сетевые тайм-ауты в тесте — параметром клиента, а не паузой.
- **Санитайзеры.** Новые задания — `QtConcurrent::run` + `QFutureWatcher` (прослойка TSan их знает); `QNetworkAccessManager` — на GUI-потоке; локальный сервер теста — тоже.
- **Справка и тема:** новое окно и док — в сравнении картинок `theme_mode`.

## Риски и затронутые инварианты CLAUDE.md

- **Инвариант 7** (фильтры и поля — пер-вкладочные): шаг 4 меняет смысл `extraction`; формулировка — в том же PR. Подставленная при открытии схема — состояние вкладки, как выбранная вручную.
- **Инвариант 4:** смена схемы идёт прежним путём `FieldSchemaController::applyToView`; подбор при открытии ставит схему ДО разбора и полей не мутирует; поздняя проба — обычная смена схемы.
- **Инвариант 3:** `SchemaFitJob` — по требованию и в пуле, на батч ничего не считается.
- **Инвариант 9:** панели окна — на `CardFrame`, поля раскладок — от `CompactStyle`.
- **Цена загрузки.** Схема теперь действует всегда, когда выбрана, а подбор ставит её сам: регексная схема замедляет разбор (ключевая — нет). Замер — в шаге 1; правило большого файла шага 5 — по его итогу.
- **Ложная подстановка.** Две схемы с похожим началом (Logback и Syslog ISO оба начинаются с метки): страхуют `specificity`, порог 0,90, корпус «каждая встроенная первая на своём и не подходит на чужих», таблица имён (выбор пользователя побеждает) и то, что вид строк не меняется.
- **Приватность подсказчика** — главный риск шага 2: логи содержат чужие данные. Меры — раздел 3 (выключен, окно согласия с точным текстом, маскировка, обрезка, ключ вне ini). Нарушение любого пункта — дефект, а не пожелание.
- **Регекс от модели.** Катастрофический регекс в схеме-ответе: бюджет времени `SchemaFit` и сторож предпросмотра; схема, не уложившаяся на образцах, отклоняется.
- **Совместимость.** Формат файла схемы и версии состояний не растут; 0.7, открывший состояние новой версии, видит прежний `extraction`.
- **Объём окна.** `SchemaEditorWindow` — новый класс вне `mainwindow.cpp`; в окне — только открытие. Операции правки — в ядре (`schemaedit`), окно их зовёт.
- **MSVC:** новые типы объявлять одним ключевым словом (`struct` везде).

## Решения за автором

Если автор не возразил, принимается рекомендованный вариант.

| Вопрос | Рекомендация |
| --- | --- |
| Схема действует без галочки (сейчас — только с «Filter blocks») | Да: выбранная схема работает сразу; «показывать только выбранные поля» — отдельный переключатель. Схемы, выбранные раньше без галочки, начнут действовать после обновления (вид строк не меняется) |
| Подбор при открытии — подставлять или предлагать | Подставлять молча (вид строк не меняется), сообщение — в строке статуса; для больших файлов с регексной схемой — предлагать, если замер покажет заметное замедление |
| Что делать, когда подходящей схемы нет | Схема по умолчанию, только если она разбирает хотя бы половину строк; иначе без схемы и кнопка Find a Schema |
| Провайдер подсказчика | Claude API по ключу пользователя. Локальная модель (сервер с OpenAI-совместимым адресом: Ollama, LM Studio) — отдельным маленьким шагом после шага 2, если автору нужна работа без отправки строк наружу: интерфейс провайдера под это готов |
| Модель по умолчанию | `claude-opus-5-5`; имя модели правится в настройках |
| Согласие на отправку | Каждый раз, с точным текстом; «больше не спрашивать» нет |
| Маскировка | Включена по умолчанию, выключается галочкой в окне согласия |
| Где хранить ключ | Переменная окружения или настройки: DPAPI на Windows, файл 0600 на Linux; в ini — никогда |
| Старый редактор блоков | Остаётся разделом «Advanced: block chain» нового окна |
| Пресеты | Сливаются со схемами, пользовательские переносятся в каталог |

## Чего не делаем

- Модель внутри программы и анализ содержимого лога нейросетью («что здесь сломалось») — только предложение схемы.
- Отправку строк без окна согласия, фоновые и автоматические запросы к модели (при открытии файла подсказчик не вызывается никогда).
- Несколько схем на один файл и автоматическое переключение схемы посреди файла.
- Разбор `key=value` внутри сообщения в отдельные поля (вернуться после этой задачи, если попросят).
- Профиль «схема + фильтры + подсветка», применяемый при открытии.
- Табличный режим строк во view (U-18) — отдельная задача; таблица образцов живёт только в редакторе.
- Перетаскивание границы поля мышью: Make Field и Merge покрывают те же случаи проще и доступны с клавиатуры.
