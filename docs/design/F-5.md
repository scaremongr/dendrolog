# F-5. Схема на вкладку, затем на файл

Статус: спроектирован 19 ноября 2026, действуют рекомендованные варианты (автор передал продуктовые решения исполнителям). Задача `F-5` из `docs/roadmap.md`, релиз 0.7. Код читался на `06aa5eb` (0.6.0). Опирается на M-2 (каталог схем и панель Log Fields — из окна в контроллер `fieldschemacontroller`, делается до шага 1) и на `docs/design/F-4.md` (ключевые схемы: вид схемы, поэтому на файл он становится вместе со схемой).

## Задача и границы

Сейчас схема полей одна на окно: выбрал «nginx access» для одной вкладки — Spring-лог в соседней потерял колонки. Слитая вкладка из лога приложения и access-лога не может разобрать оба. Нужно, чтобы вкладки не мешали друг другу, а файлы слитой вкладки разбирались каждый своей схемой.

Входит:

- схема, извлечение полей («Filter blocks») и выбор колонок — на вкладку; схема по умолчанию для новых вкладок;
- схема на файл внутри вкладки; колонки слитой вкладки — объединение по имени;
- хранение: сессия, `last-session.json`, стек `Ctrl+Shift+T`, память файла; чтение старых файлов;
- все потребители полей: парсер, индексатор, индексный стор, фильтр-воркеры, переизвлечение, Save View As, Search Results, Entry Details.

Не входит: автоматическое предложение схемы при открытии (F-6 — после этой задачи, на файл), новые виды схем (F-4), схема в сканере каталога.

## Как устроено сейчас

- **Физически схема уже на вкладку.** У каждой `LogViewWidget` свои `LogParser` (два: загрузка и дочитывание), `LogIndexer` и индексный стор со своей копией `LogPattern` (`setParserPattern`, `src/logviewwidget.cpp:233-243`; `IndexedLogStore::m_fieldPattern`, `src/indexedlogstore.h:226`). Флаг извлечения — тоже на вкладку (`setExtractionEnabled`, `:245-253`). Правила вкладка привязывает к своим полям сама (`parserFieldNames`, `:99`, `:1571`).
- **Одинаковыми их держит окно.** `MainWindow::m_conversionPattern` — одна схема; `onPatternComboChanged` → `applyPatternToAllViews` (`src/mainwindow.cpp:1621`, `:1724`) ставит её ВСЕМ вкладкам, переизвлекает поля всех резидентных записей (до 4000 — синхронно, больше — один `FieldReextraction` на все вкладки) после остановки фильтров всех вкладок, Search Results и Save View As (инвариант 4). Новая вкладка получает схему окна (`createLogViewWidget`, `:1865`), флаг и колонки окна (`:1897-1902`).
- **Log Fields — глобальная панель.** Чекбоксы колонок строятся по схеме окна (`rebuildFieldVisibilityControls`), выбор ставится всем моделям (`applyFieldVisibilityToAllViews`, `:1601`). Модель хранит выбор у себя (`LogModel::setFieldDisplaySelection` — индексы колонок).
- **Привязка правил — к схеме окна:** Text Filters Apply (`applyTextFiltersToActiveView`, `:3596-3597`) и запрос Search берут `LogPattern(m_conversionPattern).fieldNames()`.
- **Хранение.** ini `[View]`: `conversionPattern`, `fieldFilterEnabled`, `fieldVisibleNames` (`:1158-1164`). `SessionState` — одна схема (`schemaName`, `schema` — определение), `fieldExtraction`, `visibleFields` (`src/documentstate.h:150-153`); при открытии окно ставит схему ДО вкладок, `SessionController::chooseSchema` находит совпадающую по определению или добавляет «(from session)». `TabState` и память файла схему не хранят (`docs/release-checklist-0.6.0.md`: «до F-5»). Читатели `ViewState`, `TabState`, `TabSource`, `FileMemory` и `SessionState` игнорируют неизвестные ключи; `SessionState` с версией не 1 отвергается.
- **Поля — индексы схемы.** `LogEntryFields::spans[i]` — колонка `i` схемы; `formatDisplayText` и `FilterRuleSet` (`m_boundFieldIndexes`) работают индексами, имя → индекс разрешает `bindFields`. Строка без колонки правила — «не содержит»; колонки нет в схеме — правило нейтрально (`fieldMissing`).
- **Схема при загрузке, а не при показе.** Резидентные записи несут спаны с момента разбора, индексный стор извлекает по требованию своей копией. Граница записи (при включённом извлечении) и, после F-4, метка и уровень из ключей решаются при загрузке.

## Решение

### Владелец и одно значение на файл

Схема на файл повторяет путь, проверенный F-1 для кодировки:

| | Резидентная вкладка | Индексная вкладка |
| --- | --- | --- |
| Где живёт схема файла | `LogViewWidget::m_fileSchemas` (путь → схема), как `m_fileEncodings` | в `IndexedLogStore`, в записи файла рядом с декодером |
| Кто читает | парсер получает схему файла на старте прохода (загрузка, дочитывание, перечитывание) | `entryAt`, снапшоты, фильтр-воркер, поисковая база — копией, как декодер |
| Переход порога | состояние уходит в стор | обратно — во вкладку |

Схема на `LogFile` (общем для записей и потоков) отвергнута: структура разделяется между потоками без синхронизации, мутация в ней — гонка.

Значение — `FileSchema`: `LogPattern` файла и таблица «колонка схемы → колонка вкладки». Тип живёт в ядре (`src/fieldlayout.h`) вместе с раскладкой вкладки:

```cpp
struct FieldLayout {               // колонки вкладки
    QStringList columns;           // объединение по имени, только растёт
    FileSchema  schemaFor(const LogPattern& p);   // добавляет недостающие колонки в конец
};
struct FileSchema {
    LogPattern   pattern;
    QVector<int> columnOf;         // индекс поля схемы → индекс колонки вкладки
    QBitArray    hasColumn;        // какие колонки вкладки есть у этой схемы
};
```

### Поля — сразу в пространстве колонок вкладки

Парсер, индексный стор и переизвлечение кладут спаны не по индексу схемы, а по `columnOf`: поле `Level` файла nginx и поле `Level` файла Spring — одна колонка вкладки. Дальше НИЧЕГО не меняется: фильтр, `formatDisplayText`, Save View As, Search Results, Entry Details работают индексами колонок вкладки, как сейчас индексами единственной схемы. У вкладки с одной схемой `columnOf` тождественен — поведение байт в байт прежнее.

Колонки только добавляются (новая схема файла дописывает свои имена в конец), поэтому индексы уже разобранных записей не устаревают. Пересборка раскладки — только при смене схемы пользователем: тогда колонки строятся заново и поля вкладки переизвлекаются, как сейчас при смене схемы окна.

Два правила для слитой вкладки:

- **Строка, в схеме которой нет ни одной выбранной колонки, показывается сырым текстом** (`formatDisplayText` получает `hasColumn` файла). Без этого выбор «Timestamp Level Message» оставил бы пустыми все строки файла со схемой без этих колонок. Строка, схема которой колонку имеет, но строка её не заполнила, остаётся пустой, как сейчас.
- **Правило фильтра по колонке, которой нет у схемы файла, на строках этого файла даёт «не содержит»** — та же семантика, что у продолжения многострочной записи. `Include Level contains ERROR` во вкладке Spring + nginx оставляет только ошибки Spring. Нейтральным (`fieldMissing`) правило остаётся, только если колонки нет во всей вкладке.

### Что видит пользователь

| Место | Поведение |
| --- | --- |
| Комбобокс схемы (док Log Fields) | Схема активной вкладки; при смене вкладки — её схема. Выбор меняет только активную вкладку |
| «Applies to» (под комбобоксом, только у вкладки из нескольких файлов, шаг 3) | «All files» или файл вкладки. Комбобокс показывает схему выбранной цели; у «All files» при разных схемах — «(mixed)» |
| «Filter blocks» и чекбоксы колонок | Вкладки; колонки — объединение схем её файлов |
| Новая вкладка | Схема по умолчанию — последняя выбранная пользователем в комбобоксе (ключ ini `[View] conversionPattern`, смысл «по умолчанию»), флаг и колонки — тоже последние |
| «Apply Schema to All Tabs» (меню дока Log Fields и меню View) | Прежнее поведение одним действием |
| Файл, добавленный в открытую вкладку | Схема вкладки (до шага 3 — она же для всех файлов); с шага 3 — схема из памяти файла, если есть, иначе схема вкладки |
| Объединение вкладок (`addFilesFrom`) | Файлы приносят свои схемы (как кодировку); колонки приёмника растут |
| Search Results | Колонки и привязка правил — от вкладки-источника |
| Entry Details | Имена колонок вкладки; значения — поля строки |

### Смена схемы: инвариант 4 на одну вкладку

`applyPatternToAllViews` становится `applySchema(tab, target)` в контроллере M-2: остановить фоновые фильтры и Save View As (как сейчас — у всех: дёшево и не требует знать, кто читает записи этой вкладки), Search Results, если его источник — эта вкладка; переизвлечь поля записей только затронутых файлов; `reapplyFilterIfStale`. `FieldReextraction` получает схему на запись (`(entry, shared_ptr<const FileSchema>)`), а не одну на задание. Если меняется ключевая часть схемы (F-4, шаг 3), файл перечитывается тем же путём, что смена кодировки.

### Хранение

Версии форматов не растут: все новые ключи необязательные, читатели прежних версий их игнорируют.

- **`ViewState.fields`** — `{"schema":{"name","definition"},"extraction":true,"visibleFields":[…]}`: схема вкладки, флаг, колонки по именам. Пишется в `TabState` (сессия, `last-session.json`, `Ctrl+Shift+T`) и в память файла одно-файловой вкладки.
- **`TabSource.schema`** (шаг 3) — `{"name","definition"}`, только если схема файла отличается от схемы вкладки.
- **`SessionState.schema` верхнего уровня остаётся** — схема активной вкладки: её прочитает 0.6, и ею получают схему вкладки без `fields` (сессии 0.6). `visibleFields` и `fieldExtraction` верхнего уровня — так же.
- **Схема по определению:** при применении — `SessionController::chooseSchema` (совпадающая по определению, иначе добавить «(from session)»). Для памяти файла каталог не засоряется: нет совпадающего определения — вкладка берёт схему по умолчанию, строка статуса сообщает «Remembered schema X is not in the catalogue».
- **Память файла:** одно-файловая вкладка помнит схему вкладки (`ViewState.fields`), файл слитой вкладки — свою (`TabSource.schema`). Применяется сразу при открытии, как ручной выбор кодировки: схема — не фильтр, предлагать её плашкой незачем.
- Эталоны `tests/document_state/*.json` (версии 1) читаются без изменений; новые эталоны с `fields` и `schema` — рядом.

### Связи

- **M-2** — до шага 1: шаг 1 переписывает тот самый путь (`applyPatternToAllViews`, Log Fields, каталог схем), который M-2 выносит в `fieldschemacontroller`. Без M-2 шаг 1 растит `mainwindow.cpp`.
- **F-4** — ключевая схема — свойство `LogPattern`, поэтому на шаге 2 «схема на файл» даёт и «JSON-файл в слитой вкладке с обычным логом» без отдельной работы. Перечитывание при смене ключевой части (F-4, шаг 3) после шага 1 касается одной вкладки, после шага 3 — одного файла.
- **F-6** — после шага 3: предложение «похоже на X — применить?» — на файл, отказ хранится в памяти файла рядом со схемой.
- **F-2** — схема сжатого файла хранится по ключу источника (путь архива + член) — тот же ключ памяти, что F-2 PR 2 вводит для закладок; шаг 3 идёт после F-2 PR 2 (оба трогают `documentstate`, `filememorystore`).

## Проверки

- **`logstore_equivalence`** — слитая вкладка с двумя схемами (одна — ключевая F-4, когда та готова): все конфигурации фильтров, правила по общей колонке, по колонке одного файла и по колонке, которой нет во вкладке; текст показа с выбором, задевающим только один файл (сырой текст у другого).
- **`document_state`** — эталоны версии 1 (`tab-state-v1.json`, `session-v1.json`, `file-memory-v1.json`, `session-windows.json`, `session-posix.json`) читаются, и результат — прежний; новые эталоны `session-schemas.json` (вкладки с разными схемами и файл со своей) с круговым проходом; схема, которой нет в каталоге: сессия добавляет «(from session)», память — схема по умолчанию и сообщение.
- **`mainwindow_smoke`** — сценарии из таблицы PR; свип меню с новым действием; смена схемы одной вкладки не трогает выдачу Search другой.
- **`logview_state`** — триггер «колонки» уже есть; добавить «смена схемы файла в слитой вкладке» (текущая запись и вьюпорт переживают переизвлечение).
- Одна схема на всё (как в 0.6) — побайтно прежний базлайн `DENDRO_BASELINE_DUMP` на обоих бэкендах.

## Риски и затронутые инварианты CLAUDE.md

- **Инвариант 7** меняется: «Fields — глобальный» → схема, извлечение и колонки — пер-вкладочные, у файла слитой вкладки — своя схема. Формулировка — в PR 1 и PR 3.
- **Инвариант 4** — сужается до вкладки, механизм прежний (`cancelPendingFilter(wait)` → мутация на GUI-потоке → `reapplyFilterIfStale`). Search Results делит записи с источником — останавливается вместе с ним.
- **Инвариант 3** — раскладка колонок растёт при подключении файла (один раз на файл), а не на батч; `columnOf` применяется в воркере.
- **Инвариант 11** — порядок строк не зависит от схемы, кроме метки из ключей (F-4), которая решается при загрузке; слияние идёт по моменту, как сейчас.
- **Хранилище** — PR 2 трогает оба бэкенда; параллельно с другой задачей хранилища не вести.
- **Совместимость форматов** — новые ключи необязательные, версии не растут; 0.6, открывший сессию 0.7, получит схему активной вкладки для всех вкладок и при пересохранении потеряет схемы вкладок (снимок 0.6 их не знает) — приемлемо.
- **Каталог схем** — схема из сессии с определением, которого нет в каталоге, добавляется «(from session)» на каждую такую вкладку; одинаковые определения сводятся к одной записи.
- **MSVC** — `FileSchema` и `FieldLayout` объявлять `struct` везде, forward-декларации совпадают.
- **Цена** — `FileSchema` копируется в воркер, как `LogPattern` сейчас (регексы Qt разделяемые); на строку добавляется перенос спанов через `columnOf` — копия вектора из единиц элементов.

| Что такое схема по умолчанию для новых вкладок | Последняя выбранная пользователем в комбобоксе (тот же ключ ini); отдельной настройки нет |
| Нужно ли действие «применить ко всем вкладкам» | Да, «Apply Schema to All Tabs» — прежнее поведение одним действием |
| «Filter blocks» и выбор колонок | На вкладку, вместе со схемой |
| Где выбирать схему файла | В доке Log Fields строкой «Applies to: All files / файл», только у вкладки из нескольких файлов |
| Колонки слитой вкладки | Объединение по имени, в порядке схем файлов |
| Строка без выбранных колонок в слитой вкладке | Сырой текст |
| Правило по колонке, которой нет у схемы файла | «Не содержит» на строках этого файла (как у продолжения записи) |
| Схема в памяти файла | Да; применяется сразу, если определение есть в каталоге, иначе — схема по умолчанию и сообщение |
| Видимое изменение | Смена схемы больше не трогает другие вкладки; кто привык к одной схеме на окно — «Apply Schema to All Tabs» |

## Чего не делаем

- Автоматический выбор схемы при открытии (F-6 — предложение, после этой задачи).
- Схема по маске имени файла (`*.jsonl` → JSON Lines) — вернуться после F-6, если предложения окажется мало.
- Разные колонки для разных файлов в одном view (колонка показывается у всех файлов, где она есть).
- Удаление колонок из раскладки вкладки при закрытии файла — колонки только растут до смены схемы пользователем.
- Схема в сканере каталога и в фильтре сканера по содержимому.
