# R-7 — история переходов (`Alt+←` / `Alt+→`)

Задача объёма S, дизайн-документа не было; решения приняты исполнителем — самые простые обратимые.

## Как устроено

- **`NavHistory`** (`src/navhistory.*`, ядро, без виджетов) — история одной вкладки. Владелец — `LogModel`, как у `BookmarkStore`: история живёт до закрытия вкладки, переживает конверсию бэкенда, на диск не пишется.
- **Запись** — позиция в логе: `RecordKey` (R-1) плюс путь файла, номер строки и первые 200 символов текста — как у закладок. Флаги `verified` (ключ сверен после последнего сброса строк) и `lost` (строки больше нет).
- **Единственная точка записи — `LogListView::goToRow(row, NavKind)`**. Всё, что ведёт по действию пользователя, уже шло через неё (Go to, таймлайн, статистика, выдача Search, F3, F8/F7, F2 и панель закладок, «↓ N новых строк»), поэтому новый источник переходов попадает в историю сам: вид по умолчанию — `NavKind::Other`. Откуда ушли — `userSelectedRow()` (инвариант 10), без выбора — первая строка экрана. Щелчки, стрелки и прокрутка через `goToRow` не идут и не пишутся.
- **Возврат** — `LogViewWidget::navigateHistory(forward)`: `NavHistory::back/forward` находят строку, переход — `goToRow(row, NavKind::History)`: выделение, якорь, снятие follow-tail, но без записи.
- **Команды** — `navigateBack` / `navigateForward` в `ShortcutManager` (`Alt+←` / `Alt+→`), пункты `View → Navigate Back / Forward` рядом с Go to; доступность — по `canGoBack/canGoForward` активной вкладки (сигнал `LogViewWidget::navHistoryChanged`, смена вкладки). Боковые кнопки мыши над логом — сигнал `LogListView::historyNavigationRequested`.

## Решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Склейка повторов | «Шаг» (F3, F8/F7, F2 и панель закладок, выдача Search, «↓ N новых строк») того же вида, что и последний переход, когда пользователь после него не сдвинулся (откуда == текущая запись истории), заменяет прошлую цель. Серия, вернувшаяся к началу, схлопывается. Разовые переходы (Go to, таймлайн, статистика, `Other`) не склеиваются; место, куда вернулись по истории, следующий шаг не затирает | F3, F3, F3, F8 подряд, листание выдачи Search стрелками — один шаг назад. Цель разового перехода пользователь, скорее всего, читал — её терять нельзя. Правило не зависит от расстояния между строками: находки F3 бывают далеко друг от друга |
| Предел | 100 записей, старые выпадают | Запись — десятки байт плюс фрагмент; память не важна, важно не листать бесконечно |
| Новый переход после возврата | Отбрасывает «вперёд» | Как в браузере |
| Текущая позиция при `Alt+←` | Не записывается | Проще; `Alt+→` ведёт к цели перехода, а не туда, куда от неё ушли |
| Где хранить | У `LogModel` | Модель — на вкладку и живёт через конверсию; сбросы строк (`setEntries`, `removeEntriesForFile`, конверсии, `clear`) уже проходят через неё. Вкладка сообщает о сбросе мимо модели через `LogModel::invalidateFileRows` (раньше — только закладкам) |
| Сверка после сброса строк | Лениво, при возврате | Инвариант 3: на `rowsInserted` история ничего не делает. Сверенная запись — `nearestRowForKey` (у видимой строки фрагмент освежается: хвост без `'\n'` мог дописаться); несверенная — точная строка по ключу или по номеру (`nearestVisibleRowForLine`) с точной проверкой фрагмента; не совпал — `lost`, запись пропускается до следующего сброса строк файла (содержимое могли вернуть) |
| Сочетания | `Alt+←` / `Alt+→` по умолчанию были свободны (проверка уникальности — в тесте). Если пользователь уже отдал клавишу другой команде, `ShortcutManager::sequence` оставляет её той команде, а у новой — пусто | Часть U-20; показ конфликта в настройках остаётся U-20 |
| Диалог настроек | Сохраняет только строки, изменённые пользователем | Иначе пустое поле уступившей команды стало бы пустым переопределением навсегда, как только другая команда освободит клавишу |
| Возврат во время фонового F3 / F8 | Возврат отменяет их | Иначе их итог увёл бы вид от места возврата и затёр «вперёд» |
| `ShortcutManager` | Перенесён из exe в `dendrolog_widgets` | Его проверяет тест |

Ограничение: несверенную строку, скрытую фильтром, текстом не проверить — её ведёт ключ, если он есть в данных. Ключ строки без метки в переписанном файле может совпасть с чужой строкой (та же ловушка у закладок).

## Проверки

`tests/nav_history`:

- ядро на обоих бэкендах (один и два файла): назад / вперёд, отбрасывание «вперёд», склейка шагов и её разрыв видом и сдвигом, разовые переходы не склеиваются, шаг после возврата не затирает место возврата, серия, вернувшаяся к началу, переход на месте и возврат не пишутся, предел, фильтр скрывает место — ближайшая видимая;
- вкладка `LogViewWidget` на живых файлах, резидентная и индексная: каждый вид перехода → назад → вперёд против ожидаемых строк; серия F3 — один `Alt+←`; стрелки, щелчок и прокрутка не пишут; боковые кнопки мыши; «откуда» без выбора — первая строка экрана; возврат снимает follow-tail; фильтр; дозапись и «↓ N новых строк»; файл удалён (идти некуда) и создан заново (места на месте); переписан — пропавшее место пропускается, пункты недоступны; содержимое возвращено — место снова находится; возврат не создаёт записей;
- рост файла за порог: вкладка становится индексной, история та же; закрытие вкладки уничтожает историю;
- сочетания по умолчанию уникальны, `Alt+←` уступает переназначенной пользователем команде.
