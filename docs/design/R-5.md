# R-5. Состояние документа: закладки, память файла, сессии

Статус: черновик · Покрывает хранение для R-2, R-4 и R-5 · Опирается на `docs/design/R-1.md`

## Задача и границы

Входит:

- модель состояния вкладки без виджетов и её формат на диске;
- где хранятся закладки (R-2), память файла (R-4) и сессии (R-5), чем они отличаются;
- поведение при изменённом и пропавшем источнике;
- восстановление вкладок при запуске и `Ctrl+Shift+T`;
- portable-режим и несколько экземпляров.

Не входит:

- внешний вид панели закладок и пункты меню (решаются в PR задачи R-2);
- схема на вкладку (F-5) и сохранение раскладки доков (уже есть в `[Window]`).

## Как устроено сейчас

- Применённое к вкладке состояние живёт в `LogModel`: уровни, интервал времени, правила текста, маркеры (`src/logmodel.h:157-170`). Авто-обновление — во `LogViewWidget` (`src/logviewwidget.h:42-43`), слежение за хвостом и якорь выделения — в `LogListView`, только в памяти.
- Схема и выбор колонок глобальные: новая вкладка получает `m_conversionPattern` окна (`src/mainwindow.cpp:1544`), оба значения пишутся в `[View]` (`:853-859`).
- В `[Filters]` сохраняется содержимое ПАНЕЛЕЙ: профили правил и список маркеров (`src/mainwindow.cpp:871-889`). Что применено к какой вкладке, не сохраняется нигде.
- Новая вкладка стартует без фильтров (`src/mainwindow.cpp:1552-1555`, инвариант 7). `closeTab` удаляет страницу, ничего не запомнив (`:2284-2292`).
- `saveSettings` вызывается из `closeEvent` (`src/mainwindow.cpp:624-631`); списка вкладок в настройках нет.
- Сериализация готова: `FilterRuleSet` и `HighlightPattern` умеют JSON (`src/filterruleset.h:108-109`, `src/textmatchhighlighter.h:53-54`). Привязка правил к колонкам — производное состояние и не сериализуется (`src/filterruleset.h:124-127`).
- Жёлоб шириной 12 px рисуется в одном месте (`src/LogListView.h:297`, `src/LogListView.cpp:719-730`). Роли, не меняющие текст, перерисовываются без сброса кэшей (`src/LogListView.cpp:319-325`).
- Повторный запуск отдаёт файлы первому экземпляру и выходит; `--new-instance` и stdin открывают своё окно с тем же `configDir` (`src/main.cpp:122-127`, `:146-153`).
- Каталог настроек — рядом с exe в portable-режиме, иначе `AppConfigLocation` (`src/appsettings.cpp:25-41`).

## Решение

### Где живёт состояние во время работы

Вторая копия правды не заводится. Фильтры и маркеры остаются в `LogModel`. Новое состояние получает владельца в ядре; виджеты его только показывают.

| Состояние | Владелец во время работы | Библиотека |
| --- | --- | --- |
| Уровни, время, правила, маркеры | `LogModel`, как сейчас | core |
| Закладки с заметками | новый `BookmarkStore`, по одному на вкладку | core |
| Сохранённые идентификаторы и их разрешение | `RecordLocator` из R-1 | core |
| Текущая строка и смещение вьюпорта | `LogListView`; снимается и ставится через новый публичный метод | widgets |
| Авто-обновление, слежение за хвостом, список файлов | `LogViewWidget`, как сейчас | widgets |
| Схема, выбор колонок | `MainWindow`, как сейчас (до F-5) | exe |

### Модель

```cpp
// src/documentstate.h — чистые данные и JSON, без QObject
struct BookmarkState { int source; RecordId id; QString note; QString preview; QDateTime created; };
struct ViewState {
    QStringList levels;  QDateTime timeFrom, timeTo;    // пустое = граница открыта
    QJsonObject textRules;  QJsonArray markers;          // форматы FilterRuleSet и HighlightPattern
    int currentSource = -1;  RecordId current;  int viewportOffset = 0;
    bool followTail = false, autoReload = false;
};
struct TabState     { QVector<SourceIdentity> sources; QVector<BookmarkState> bookmarks; ViewState view; };
struct SessionState { QString schemaName, schemaPattern; bool fieldFilter; QStringList visibleFields;
                      int activeTab; QVector<TabState> tabs; };
```

`preview` — до 200 символов текста строки. Нужен, чтобы закладка оставалась понятной, когда её строку найти нельзя.

### Три хранилища

| | Память файла (R-4) | Последняя сессия (R-5) | Файл сессии (R-5) |
| --- | --- | --- | --- |
| Где | `<configDir>/memory/*.json`, по файлу на лог | `<configDir>/last-session.json` | Где скажет пользователь, `*.dlsession` |
| Что | Закладки файла; `ViewState` — только если файл был во вкладке один | `SessionState` целиком | `SessionState` целиком |
| Когда пишется | Через 2 с после правки закладки; при закрытии вкладки и выходе | При выходе | По команде «Сохранить сессию» |
| Когда читается | При каждом открытии файла | При запуске, если включено | По команде «Открыть сессию» |
| Пути | Абсолютный | Абсолютные | Абсолютный и относительный к файлу сессии |

Правило приоритета: вкладка, открытая из сессии, берёт фильтры, маркеры и позицию из сессии. Закладки объединяются с памятью файла, чтобы более свежие не пропали; у совпавших по строке заметка берётся из сессии. Дальше память обновляется как обычно. Файл сессии — снимок: сам не обновляется, понятия «текущая сессия» в первом объёме нет.

Все три пишутся через `QSaveFile`. В заголовке — `format`, `version`, `hash`. Читатель игнорирует неизвестные ключи и отказывается от файла с большей версией, не трогая его.

```json
{ "format": "dendrolog-file-memory", "version": 1, "hash": "sha1-64",
  "source": { "path": "C:/logs/app.log", "size": 1048576, "head": "9f0c…", "tail": "3ca1…" },
  "bookmarks": [ { "line": 185, "text": "a1b2…", "preview": "2026-07-16 09:20:31.554 [db-pool] ERROR …",
                   "note": "первый таймаут", "created": "2026-11-17T10:00:00Z" } ],
  "view": { "current": { "line": 185, "text": "a1b2…" }, "offset": 120, "levels": [], "markers": [] } }
```

### Память файла: ключ и поиск

Имя файла памяти — отпечаток нормализованного абсолютного пути (на Windows без учёта регистра). Внутри лежит `SourceIdentity`.

1. По пути найден файл памяти, источник Valid — состояние применяется.
2. По пути найден, источник Changed (ротация, перезапись) — память относится к прежнему содержимому. Если в ней есть закладки, она переименовывается в отсоединённую и остаётся в каталоге; иначе удаляется.
3. По пути не найдено — вторичный поиск по содержимому: отпечаток начала открываемого файла сравнивается с отпечатками в каталоге памяти. Совпало и источник Valid — память переезжает на новый путь. Так закладки находят лог, распакованный в другую папку, и `app.log.1` после ротации.

Каталог — источник правды; перечень его идентичностей читается один раз за запуск. Лимит — 200 файлов, вытесняются давно не открывавшиеся; память с закладками сама не вытесняется.

Многофайловая вкладка: закладки каждого файла уходят в его память, `ViewState` не сохраняется — он принадлежит сессии.

### Применение состояния

- Память ищется в `addLogFile` до старта загрузки, поэтому идентификаторы попадают в `RecordLocator` раньше первого батча.
- Маркеры, а для сессии и фильтры, ставятся в модель до данных. Правила перед этим привязываются к текущей схеме через `bindFields`, как в `applyTextFiltersToActiveView` (`src/mainwindow.cpp:3223-3228`).
- Позиция ставится, когда локатор разрешил текущую строку. Если пользователь успел выбрать строку или прокрутить вид, позиция не ставится.
- Было включено слежение за хвостом — включается оно, позиция не восстанавливается.
- Панели Text Filters и Row Highlighters не переписываются: они показывают свои правила, а не применённые к вкладке.

### Изменённый или пропавший источник

| Случай | Память файла | Сессия |
| --- | --- | --- |
| Файл есть, Valid | Применяется | Вкладка восстанавливается |
| Файл есть, Changed | Файл открывается чистым; прежние закладки — в панели серыми, с текстом и заметкой, в логе не показаны | То же, плюс строка в отчёте о восстановлении |
| Файла нет | — | Источник пропускается; отчёт предлагает указать файл или убрать его из вкладки |
| Указан другой файл | Принимается, если источник Valid; иначе закладки остаются серыми | То же |
| stdin | Не сохраняется | Вкладка в сессию не попадает |

Запуск не показывает модальных окон: о пропущенном сообщает строка состояния со ссылкой на отчёт.

### Восстановление вкладок и `Ctrl+Shift+T`

- При запуске: если настройка включена и окно первичное, вкладки восстанавливаются из `last-session.json`, затем открываются файлы из командной строки. При выключенной настройке стартовый экран показывает ссылку «Восстановить прошлый сеанс».
- `closeTab` перед удалением страницы снимает `TabState` в стек окна, последние 10. `Ctrl+Shift+T` восстанавливает верхний тем же путём, что и сессия.

### Portable-режим и несколько экземпляров

- `memory/` и `last-session.json` лежат в `configDir`, поэтому в portable-режиме переезжают вместе с папкой. Пути внутри абсолютные; на другой машине срабатывает вторичный поиск по содержимому.
- Вторичный экземпляр (`--new-instance`, stdin) не восстанавливает прошлую сессию и не пишет `last-session.json`. Память файлов он читает и пишет; при одном файле в двух окнах побеждает последняя запись.
- Файлы, переданные первичному экземпляру через `SingleInstance`, открываются новыми вкладками и восстановления не запускают.

## Отвергнутые варианты

| Вариант | Почему нет |
| --- | --- |
| Хранить в `DendroLog.ini` | Общий файл настроек всех экземпляров; закладкам с текстом и сотням записей в нём не место |
| Файл-спутник рядом с логом | Каталог лога часто только для чтения или чужой; мусор рядом с логами |
| Один общий файл памяти | Гонка между экземплярами портит всё сразу; растёт без границ |
| Ключ памяти только по содержимому | Отпечаток начала нестабилен, пока файл короче 4 КБ |
| Сессия со ссылками на память файлов | Сессию нельзя передать коллеге вместе с логами |
| Отдельная копия фильтров в `DocumentState` | Два источника правды с `LogModel` |
| Автосохраняемая «текущая сессия» | Требует учёта несохранённых изменений; отложено до запроса |

## Проверки

- Круговой проход каждого формата; эталонные файлы версии 1 лежат в тестах и читаются всеми будущими версиями.
- Файл с версией выше известной не применяется и не перезаписывается.
- Прерванная запись не портит прежний файл.
- Закладка на строке, скрытой фильтром: переход ведёт к ближайшей видимой, отметка возвращается со снятием фильтра.
- Восстановление на индексном бэкенде: позиция ставится, когда строка проиндексирована, без ожидания конца файла.
- Память файла, открытого вторым во вкладку: закладки применились, `ViewState` нет.

## Риски и затронутые инварианты CLAUDE.md

- Инвариант 7: сессия и `Ctrl+Shift+T` ставят новой вкладке фильтры, память файла — маркеры. Формулировку инварианта нужно дополнить в PR 3 и PR 4.
- Инвариант 10: восстановленная текущая строка ставится как выбор пользователя, с выделением; если пользователь уже действовал, не ставится.
- Инвариант 3: `BookmarkRole` отвечает за O(1) — `keyAt` плюс поиск в хэше; на батч ничего не пересчитывается.
- Инвариант 4: состояние не трогает поля записей.
- Инвариант 9: панель закладок — на `CardListArea` или списке со стилем `CompactStyle`.
- `mainwindow.cpp` не должен вырасти: снятие, применение и хранение — в ядре и `LogViewWidget`, окно только вызывает.
- В каталоге настроек появляются пути к логам и фрагменты их строк. В portable-режиме на съёмном носителе это уезжает вместе с программой.
- Раздел «Данные на диске» в `CLAUDE.md` и обе справки обновляются в PR 3 и PR 5.

| Вопрос | Рекомендация |

| Применять ли фильтры из памяти файла сразу при открытии? | Нет. Закладки, позиция и маркеры — сразу; фильтры сохраняются, а строка состояния предлагает «Вернуть фильтры прошлого раза». Сессия и `Ctrl+Shift+T` возвращают фильтры сразу |
