# F-18. Открыть место в коде

Статус: спроектирован 26 ноября 2026, одобрен автором («из нового предложенного одобряю — открыть место в коде»). Код читался на `43e04f7`. Объём M, один шаг, дорожка A (`LogListView`).

## Задача и границы

В стек-трейсе и в строке лога стоит `App.java:42` или `File "/srv/app/x.py", line 10` — щелчок должен открыть этот файл в редакторе кода на нужной строке. Сейчас контекстное меню умеет только «Open File» для выделенного мышью пути (`LogListView.cpp`, `QDesktopServices::openUrl`): без номера строки, только для существующего абсолютного пути и только после выделения.

Входит: распознавание места в коде под курсором, поиск файла в папках с исходниками, запуск редактора по шаблону команды, пункт контекстного меню в логе и ссылки в Entry Details.

Не входит: сопоставление номера строки с версией кода (git blame, поиск коммита), соответствие путей контейнера и машины по явной таблице, декомпиляция и переход по имени класса без файла.

## Что распознаётся

Новый модуль ядра `src/sourcelocator.*`, функция `SourceLocation locationAt(QStringView line, int pos)` — место, в которое попадает позиция, или «нет»; `locationsIn(line)` — все места строки. Результат: путь или имя файла как в тексте, строка, колонка (0 — нет), подсказка пакета (у Java).

| Форма | Пример | Откуда |
| --- | --- | --- |
| `путь:строка[:колонка]` | `src/app/main.cpp:42`, `/srv/x.js:10:5`, `C:\src\a.cs:15` | Go, Rust, Node, gcc / clang, Ruby, glog |
| `путь(строка[,колонка])` | `main.cpp(42)`, `Form1.cs(42,13)` | MSVC, .NET-сборка |
| `(Файл:строка)` после имени метода | `at com.example.App.run(App.java:42)` | Java, Kotlin, Scala — пакет `com/example` запоминается подсказкой |
| `File "путь", line N` | `File "/srv/app/x.py", line 10, in handler` | Python |
| `in путь:line N` | `in C:\src\Foo.cs:line 42` | .NET |

Имя файла обязано иметь расширение из букв и цифр (1–5 знаков) — иначе `12:30:45` и `host:8080` сошли бы за место в коде. Правила — одним ручным сканером и эталонным регексом на каждую форму; их равенство закреплено тестом, как у меток времени.

## Как находится файл

`SourceResolver` (там же, ядро):

1. Путь абсолютный и файл существует — он.
2. Иначе — поиск в **папках с исходниками** (Settings → General → Source folders, список; пусто — пункт меню ведёт в настройки). Подходят файлы, чей путь оканчивается текстом из лога по целым компонентам (`app/main.cpp` находит `…/proj/src/app/main.cpp`); для Java — `…/com/example/App.java`; голое имя — все файлы с этим именем.
3. Кандидаты ранжируются по длине совпавшего хвоста; один — открывается сразу, несколько — подменю (до 10, пути от корня папки), ни одного — «Not found in source folders».

Перечень файлов строится лениво в пуле при первом обращении и при смене списка папок: `QDirIterator`, каталоги `.git`, `node_modules`, `build`, `target`, `out`, `bin`, `obj`, `.venv`, `__pycache__` пропускаются, предел — 300 000 файлов (дальше — сообщение, а не тихая обрезка). Хранится «имя файла → пути»; за изменениями папок не следим — пункт «Rescan Source Folders» в настройках. Пока перечень строится, меню показывает «Scanning source folders…» и открывает по готовности.

## Как открывается

Settings → General → Code editor:

| Вариант | Как запускается |
| --- | --- |
| VS Code (по умолчанию, если установлен обработчик `vscode:`) | `QDesktopServices::openUrl("vscode://file/<путь>:<строка>:<колонка>")` — без поиска `code` в `PATH` и без `code.cmd` |
| Своя команда | шаблон вида `"C:\Program Files\Notepad++\notepad++.exe" -n{line} {file}`; подсказки-образцы для IntelliJ IDEA (`idea64.exe --line {line} {file}`), Notepad++, Sublime Text (`subl {file}:{line}:{column}`), Vim |
| Системная программа | `QDesktopServices::openUrl` файла, без номера строки |

Своя команда запускается `QProcess::startDetached(программа, аргументы)`: шаблон режется на аргументы ДО подстановки, значения подставляются внутрь уже готовых аргументов. Оболочка не участвует никогда, поэтому имя файла с `&`, кавычками или пробелами не может стать командой. По той же причине `.cmd` и `.bat` в качестве программы не принимаются (настройки говорят: укажите exe). В команду попадает только путь СУЩЕСТВУЮЩЕГО файла, найденного на диске, — текст из лога напрямую не подставляется.

## Где в интерфейсе

- Контекстное меню строки лога: «Open in Editor — App.java:42», если под курсором или в выделении есть место в коде; несколько кандидатов — подменю. Выделять текст не нужно.
- Команда «Open Source Location» (`ShortcutManager`, по умолчанию `Ctrl+Enter`): первое место в коде текущей строки.
- Entry Details: в полном тексте записи места в коде — ссылки; стек-трейс читают именно там.
- Двойной щелчок по токену-месту в логе выделяет его целиком (`texttoken`: новый вид токена), как сейчас путь.

## Проверки

Новый тест `tests/source_locator` (ядро и немного виджетов):

- таблица форм → путь, строка, колонка, пакет; не-места (`12:30:45`, `host:8080`, `v1.2:3`, URL с портом) не распознаются; ручной сканер против эталонного регекса на корпусе стек-трейсов Java, Python, .NET, Go, Node, Rust, C++;
- поиск во временном дереве (`QTemporaryDir`): абсолютный путь, хвост пути, пакет Java, голое имя с несколькими кандидатами и их порядок, пропуск служебных каталогов, предел числа файлов, смена списка папок;
- построение команды: шаблон и «трудные» имена (пробелы, `&`, `^`, кавычки, кириллица) → точный список аргументов; `.cmd` отклоняется; запуск — подменяемой функцией, процессы тест не стартует;
- `mainwindow_smoke`: пункт меню на строке со стек-трейсом, `Ctrl+Enter`, ссылка в Entry Details — через ту же подмену запуска.

## Риски

- **Строка лога — недоверенный текст.** Защита — раздел «Как открывается»: без оболочки, только существующий файл.
- **Ложные срабатывания** на `слово:число` — требование расширения и корпус не-мест.
- **Большое дерево исходников** — перечень в фоне, предел, служебные каталоги пропускаются; на GUI-потоке — только поиск по готовой таблице.
- **Инвариант 8** (`LogListView` со своей геометрией): меню берёт позицию символа под курсором тем же путём, что выделение текста мышью, — новой геометрии нет.
