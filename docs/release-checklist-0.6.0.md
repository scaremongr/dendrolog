# Релиз 0.6.0: что решено без автора и что проверить руками

Подготовлено 19 ноября 2026 релизной сессией. Релиз выпущен 19 ноября 2026: тег `v0.6.0`
на коммите `a98b246` («Release v0.6.0: выпуск с вершины main»), файлы — на
странице релиза https://github.com/scaremongr/dendrolog/releases/tag/v0.6.0.
Тег поставил конвейер (автор разрешил сессии-планировщику теги и релизы
19 ноября 2026) — не на первый релизный коммит `a12615b`: после него в
релиз вошли пять исправлений (перезапись файла той же длины, порядок записей
памяти файла, итог в строке статуса, окно `--new-instance` и единственный
экземпляр, файл схемы, который не разобрался) и параллельный прогон тестов.

## Решения, принятые без автора в 0.6

Автор передал продуктовые решения исполнителям (`docs/roadmap.md`,
«Процесс»). Ниже — умолчания и компромиссы этапа, которые стоит знать и,
возможно, пересмотреть. Формат: решение — почему — как изменить.

| Решение | Почему | Как изменить |
| --- | --- | --- |
| **Память файла включена по умолчанию.** В каталоге настроек появляется `memory/` — по JSON на открытый лог: путь лога, закладки с заметками и первыми ~200 символами строки, маркеры, фильтры, позиция, ручной выбор кодировки; до 200 файлов, с закладками не вытесняются | Без этого закладки исчезали бы при закрытии вкладки — смысл R-2 и R-4 пропадает. Пользователь переносимой сборки получает `memory/` рядом с exe | Умолчание — `AppSettings::rememberFileState` (`[App] rememberFileState`, `src/appsettings.cpp`). Пользователь выключает и чистит в Settings → General → File memory. В CHANGELOG 0.6.0 это в Changed |
| **Восстановление прошлой сессии при запуске выключено.** Вместо этого ссылка «Restore previous session» на стартовом экране | Открытие десятка гигабайтных логов при каждом запуске хуже лишнего щелчка; так же решено в `docs/design/R-5.md` | `[App] restoreSessionOnStartup`, умолчание в `AppSettings::load` |
| **Окно с вкладками при выходе заменяет непросмотренную прошлую сессию** — даже если ссылкой «Restore previous session» не воспользовались. Окно без вкладок файл не трогает | Как у браузеров; иначе при выключенной настройке файл застыл бы навсегда | Резервная копия предыдущего `last-session.json` — `SessionController::saveLastSession`; заводить задачей, если попросят |
| **Последняя сессия пишется только при штатном выходе.** Аварийное завершение и выход вместе с сеансом ОС без `closeEvent` её не пишут; автосохранения нет | Решение задачи R-5: проще, нет записи на диск по таймеру | Автосохранение по таймеру в `SessionController`; задачей в roadmap |
| **Фильтры из памяти файла предлагаются, а не применяются**: плашка «Restore Filters» над логом. Закладки, маркеры и позиция возвращаются сразу. Сессия и `Ctrl+Shift+T` возвращают фильтры сразу | Отфильтрованный без спроса файл выглядит «пустым», а пользователь не помнит, что фильтровал его неделю назад | `StateFilters::Offer` в `LogViewWidget::addLogFile` → `Apply` |
| **Отпечаток строки не различает строки, отличающиеся только не-ASCII текстом** (серия символов ≥ U+0080 — один заполнитель) | Отпечаток одинаков на обоих бэкендах и в любой кодировке файла, без декодирования; первая защита — номер строки и идентичность файла. Закладка в переписанном файле может «найтись» на строке того же номера, отличающейся только кириллицей | Сменить алгоритм — новая версия формата `RecordFingerprint` (`src/recordid.h`), старые закладки придётся перепроверять; не рекомендуется без жалоб |
| **`Ctrl+F2` — закладка, Directory Scanner — `Ctrl+F10`** (было `Ctrl+F2`). Закладки: `Ctrl+F2` / `F2` / `Shift+F2`, как в привычных редакторах | Привычная тройка клавиш важнее старого места панели | `ShortcutManager` (`src/shortcutmanager.cpp`). Клавиша, которую пользователь сам отдал другой команде, остаётся у неё, новая команда — без клавиши; в Settings это пока не показано (U-20) |
| **Кодировка: решение по малому свидетельству предварительное** (меньше 256 байтов ≥ 0x80) и пересматривается по мере чтения и дозаписи; **запасная кодировка — по языку системы** (кириллица → Windows-1251, иначе Windows-1252) | Один битый байт в UTF-8-логе не должен делать весь файл однобайтным; угадывать «кириллица или западная» по одному слову ненадёжно | Порог — `kFinalHighBytes` (`src/textencoding.h`); запасная — Settings → General → Non-UTF-8 files, умолчание — `TextEncodings::systemFallback` |
| **UTF-16/32 во вкладке с другими файлами и выше порога индексного бэкенда не поддерживается** — понятное сообщение вместо «Failed to parse» | Индексатор однобайтный по построению; UTF-16-логи редки | Отдельная задача, если появятся жалобы |
| **Одно-файловая индексная вкладка (файл больше 512 МБ) не сортирует строки по времени** — тот же файл ниже и выше порога может показываться в разном порядке | Нулевая цена памяти на огромном файле (известно с 0.4) | `docs/roadmap.md`, S-3/S-4 |
| **Схема полей не хранится в памяти файла**, только в сессии | Схема пока глобальная на окно; сохранять её на файл бессмысленно до F-5 | F-5 (0.7) |
| **Show in Full Log оставляет Row Highlighters** и приостанавливает уровни, время и текстовые правила; правка любого фильтра во время показа его заканчивает | Подсветка не скрывает строк — она и нужна, чтобы найти своё в полном логе | `FullLogController` (`src/fulllogcontroller.*`) |

## Ручная проверка на Windows (15–20 минут)

Только то, что offscreen-тесты не проверяют или что ни разу не запускалось на
настоящем дисплее. Логика всех пунктов покрыта тестами (`ctest`, 26 тестов, в
том числе оконный смоук `tests/mainwindow_smoke` и сценарий обновления с
0.5.0 в нём).

**Где взять сборку.** Страница релиза
https://github.com/scaremongr/dendrolog/releases/tag/v0.6.0: установщик
`DendroLog-0.6.0-setup.exe` и `DendroLog-0.6.0-win64-portable.zip` (версия
внутри — 0.6.0: Help → About DendroLog).

**Подготовка.** Установленная 0.5.0 с настройками, которыми пользовались
(хотя бы одно своё сочетание клавиш, своя схема полей, сдвинутые доки).
Лог больше 512 МБ (`python scripts/generate_test_log.py`), лог в cp1251 и
в cp866 (например, вывод `dir` в `cmd` с кириллическими именами:
`cmd /c "dir C:\Windows > dir866.log"` при кодовой странице 866).

| # | Шаг | Ожидается |
| --- | --- | --- |
| 1 | Установить поверх 0.5.0 установщиком, запустить | Версия 0.6.0 в About. Ни одного сообщения при запуске. Доки на прежних местах, свои схемы и недавние файлы на месте, тема прежняя. Своё сочетание работает; `Ctrl+F10` открывает Directory Scanner, `Ctrl+F2` ставит закладку. Если своё сочетание было на `F2`, `Ctrl+Shift+T`, `Ctrl+Shift+L` или `Alt+←`, оно осталось у своей команды, а у новой в Settings → Shortcuts пусто |
| 2 | Распаковать portable ZIP в новую папку, положить рядом файл `portable`, запустить | Настройки, `memory\` и `last-session.json` появляются рядом с exe, профиль `%LOCALAPPDATA%\DendroLog` не меняется |
| 3 | Открыть лог с ошибками, поставить 2–3 закладки (`Ctrl+F2`), одной дать заметку (контекстное меню строки → Edit Bookmark Note…), открыть панель Bookmarks (`Ctrl+F11`), запустить поиск в панели Search | На скроллбаре видны отметки: ошибки (красные) и предупреждения (жёлтые) справа, закладки посередине, совпадения Search слева; строка на экране — отметка внутри ползунка. Ленточка закладки в левом поле |
| 4 | Включить фильтр уровня Error, выбрать строку, `Ctrl+Shift+L`, затем кнопка **Return to Filtered View** на плашке | Плашка над логом «Showing the full log: the filters of this tab (…) are paused.» читается, кнопка не обрезана; строка остаётся на том же месте экрана в обе стороны |
| 5 | Выключить Follow Tail, прокрутить вверх растущий лог (`DendroLog` + дописывать в файл, например, `for /l %i in (1,1,1000) do @echo 2026-11-19 10:00:00 INFO line %i >> grow.log`) | Плашка «↓ N new lines» внизу view считает строки, щелчок ведёт к первой новой. С включённым Follow Tail вид едет за хвостом |
| 6 | Открыть cp1251-лог и cp866-лог | Текст кириллицей, а не `�`. Индикатор кодировки в строке статуса: Windows-1251 / IBM866 (auto). Щелчок по индикатору → выбрать другую → текст меняется, строка и место на экране те же; **Detect automatically** возвращает |
| 7 | Шаги 3, 4 и 6 при масштабе экрана 150 % (Параметры → Дисплей) и в тёмной теме (Settings → Appearance → Theme: Dark), затем в светлой | Отметки скроллбара, плашки «Restore Filters», «Return to Filtered View», «↓ N new lines» и индикатор кодировки не размыты, не обрезаны и читаются в обеих темах; смена темы перекрашивает их сразу |
| 8 | Закрыть вкладку с закладками и фильтром, открыть файл снова из Recent Files | Закладки с заметкой и позиция на месте; плашка **Restore Filters** — щелчок возвращает фильтр |
| 9 | Из Проводника бросить в окно: файл, папку, файл `.dlsession` (сохранить его заранее: File → Save Session As…) | Файл открывается вкладкой; папка — в Directory Scanner со сканом; сессия добавляет свои вкладки к открытым |
| 10 | Сохранить сессию с двумя вкладками в папку вместе с логами, перенести папку целиком в другое место (или на другой диск), открыть сессию (File → Open Session…) | Вкладки, фильтры, закладки и позиция на месте; файлы найдены по относительному пути. | 11 | При открытом окне запустить `DendroLog.exe другой.log` из `cmd`, затем `DendroLog.exe --new-instance другой.log` | Первый — файл открывается вкладкой в уже открытом окне, окно выходит вперёд; второй — отдельное окно |
| 12 | `cmd /c "type app.log \| "C:\Program Files\DendroLog\DendroLog.exe" -"` (и с `--encoding cp866` для вывода консольной программы) | Отдельное окно с растущей вкладкой stdin; кириллица читается; после закрытия в Recent Files нет временного файла |
| 13 | Открыть две вкладки, закрыть окно, запустить снова | Стартовый экран предлагает **Restore previous session**; щелчок возвращает вкладки. Включить Settings → General → Sessions → Restore the tabs…, перезапустить — вкладки открываются сами |
| 14 | Закрыть вкладку, `Ctrl+Shift+T` | Вкладка вернулась на своё место с фильтрами, закладками и позицией |
