# DendroLog — Краткая справка

Быстрый просмотрщик больших лог-файлов: вкладки с несколькими файлами,
извлечение полей, фильтрация, подсветка и дочитывание «на лету».

> Подсказка: любая горячая клавиша ниже настраивается в **Tools → Settings → Shortcuts**.

---

## Открытие логов

- **Открыть файл(ы)** — `File → Open` (`Ctrl+O`) или кнопка с папкой на панели инструментов. Несколько файлов открываются в одной вкладке и сливаются по времени; такая вкладка называется по первому файлу, например `app.log +2`.
- **Перетащите файлы** в любое место окна, чтобы открыть их. **Перетащите папку** — она откроется в Directory Scanner: панель покажется, скан запустится. Файлы и папки вместе: файлы открываются, папка сканируется. Сканер показывает одну папку, поэтому из нескольких сканируется первая.
- **Командная строка** — `DendroLog app.log other.log` открывает файлы, `DendroLog C:\logs` сканирует папку; правила те же, что при перетаскивании. `program | DendroLog -` читает вывод программы как растущий лог. `--encoding <имя>` задаёт кодировку файлов и потока (см. «Кодировки»).
- **Вывод команды** — `File → Open Command Output…` запускает команду и открывает её вывод (stdout и stderr вместе) растущим логом с авто-обновлением и follow-tail: `kubectl logs -f deploy/api`, `journalctl -f`, `adb logcat`. В диалоге — команда, рабочая папка и 20 недавних команд в выпадающем списке. Без **Run through the shell** запускается одна программа: аргументы делятся по пробелам, двойные кавычки их объединяют — без конвейеров, перенаправлений и переменных; с галочкой строка уходит как есть в `/bin/sh -c` (Windows: `cmd.exe /c`). Плашка над логом показывает команду и состояние — `Running (PID …)`, `Process exited with code N`, `Stopped`, `Could not start: …` — и кнопки **Stop** и **Restart** (строки нового запуска дописываются ниже); у завершённой команды в имени вкладки — `■`. Строки после выхода процесса остаются. **Закрытие вкладки завершает процесс**: сначала вежливо (SIGTERM всей группе процессов в Linux), через 3 секунды принудительно, вместе с детьми конвейера shell; временный файл вывода затем удаляется. Команда запускается только кнопкой **Run**: вкладки команд не сохраняются ни в сессиях, ни в последней сессии, ни в памяти файла, ни в списке закрытых вкладок.
- **Стартовый экран** — пока нет ни одной вкладки, окно показывает кнопки открытия файлов и сканирования папки, а недавние файлы — ссылками.
- Панель **Directory Scanner** — поиск лог-файлов в папке по расширениям и открытие одного или нескольких сразу (`File → Scan Directory…`).
- **Recent Files** — `File → Recent Files` хранит 10 последних файлов, как бы их ни открыли (в том числе из Directory Scanner); **Clear Recent Files** очищает список. Поток из пайпа (`program | DendroLog -`) и вывод команды в список не попадают: после закрытия окна их уже нет.
- **Сжатые логи (`.gz`)** открываются как обычные — из `File → Open`, перетаскиванием, из командной строки, Recent Files и Directory Scanner. gzip узнаётся по байтам, а не по имени. Файл распаковывается в фоне во временный файл (в каталоге кэша приложения): в строке статуса — `Unpacking app.log.gz… 43 %`, кнопка **Cancel Unpacking** рядом останавливает распаковку; закрытие вкладки — тоже. Вкладка, её подсказка, Entry Details, панель Bookmarks и **Copy Path** показывают архив; **Show in Folder** открывает папку архива; в подсказке — и размер распакованной копии: она занимает место на диске, пока вкладка открыта. Повреждённый архив или нехватка места называются с причиной; `F5` пробует снова. Закладки, память файла и сессии запоминают архив: открытый позже `.gz` находит свои закладки; сессия, сохранённая (или вкладка, закрытая), пока архив распаковывается, его не теряет — при открытии он распакуется заново. Кодировка, выбранная в строке статуса во время распаковки, применяется к распакованному файлу. Архивы с набором файлов (`.zip`, `.tar`, `.tar.gz`) открываются в Directory Scanner — см. ниже.
- **Архивы `.zip`** открываются в Directory Scanner — из `File → Open`, перетаскиванием, из командной строки и Recent Files (zip под другим именем узнаётся по байтам). Логи из архива (имена по расширениям сканера и их `.gz`) извлекаются в фоне во временную папку и показываются деревом папок; вместо пути — имя архива, кнопка **←** возвращает папку, показанную до архива, и удаляет извлечённые файлы. Файл, открытый оттуда, — вкладка с именем файла, в подсказках — `bundle.zip › logs/app.log`; в Recent Files попадает архив. Закладки, память файла и сессии запоминают архив и имя файла в нём (у каждого файла архива своя память) — при открытии файл извлекается из архива заново. `.gz` внутри zip открывается текстом. Имена, выводящие за папку извлечения (`..`, абсолютные пути, буквы дисков), и ссылки пропускаются, недопустимые в Windows имена переименовываются, файлы с паролем пропускаются — об этом говорит строка статуса; имя, отличающееся от другого только регистром, получает `~2` перед расширениями (`app~2.log.gz`); место на диске проверяется до начала.
- **Архивы `.tar`, `.tar.gz` и `.tgz`** — так же, как `.zip`: Directory Scanner показывает их логи, файл, открытый оттуда, — вкладка, в подсказках `bundle.tar.gz › logs/app.log`, закладки и сессии его запоминают. Читаются архивы ustar, GNU и pax, в том числе с длинными именами. tar узнаётся по байтам: `.gz` с tar внутри уходит в сканер, а `.gz` с одним логом по-прежнему открывается вкладкой. Ссылки и устройства пропускаются, как опасные имена; место на диске проверяется до начала (у `.tar.gz` — не меньше размера архива) и по ходу.
- **Закрыть вкладку** — `Ctrl+W`, крестик вкладки или средняя кнопка мыши.
- **Save View As** — `File → Save View As…` (`Ctrl+Shift+S`). Сохраняет именно то, что сейчас видно во view (активные фильтры **и** выбор Log Fields) в **новый** файл. Открытые файлы не перезаписываются.
  - **Формат** — фильтр в диалоге или расширение имени: текст (`.log`, `.txt` — как показано), **CSV** (`.csv`) или **JSON Lines** (`.jsonl`, `.ndjson`). Колонки таблицы — показанные колонки Log Fields (если показана сырая строка — все колонки схемы), перед ними `_time` (момент строки в ISO 8601 с местным смещением; без метки — пусто, в JSON — `null`) и у вкладки из нескольких файлов `_file`. Колонка **Message** есть всегда: строка без распознанных полей (продолжение записи, стек) пишет в неё свой текст целиком, остальные колонки пустые; так же строка, в которой схема узнала только начало (например, метку и уровень) без сообщения. Колонка схемы с тем же именем, что `_time` или `_file`, получает суффикс `~2`. Значения файлов JSON Lines и logfmt — раскодированные (`\"`, `\n`, `\uXXXX` — сами символы).
  - CSV — по RFC 4180: запятая, кавычки только где нужно, `CRLF` между записями, UTF-8 с BOM (Excel иначе прочтёт его в кодировке Windows); перевод строки внутри значения — в кавычках. JSON Lines — объект на строку, UTF-8 без BOM. Значения пишутся как есть: текст лога, начинающийся с `=`, Excel может принять за формулу.
- Сохранение идёт в фоне: окно остаётся рабочим, прогресс виден в строке статуса, кнопка **Cancel Save** рядом останавливает экспорт. Строки берутся такими, какими были в момент начала сохранения, — фильтрация и прокрутка во время экспорта файл не меняют. Отменённый экспорт оставляет прежний файл результата как был.
- Защита экспорта действует и при обращении к открытому файлу через другой путь или файловую ссылку. Результат заменяет выбранный файл только после успешной записи целиком; при сбое показывается ошибка, а прежний файл результата сохраняется.
- Список расширений (например `log, txt`) общий для открытия, сохранения и сканера — задаётся в **Settings → General**.

## Чтение представления

- **Вкладки** — каждая вкладка независима; фильтры/маркеры свои у каждой.
- **Маркер `›` в желобке** — начало логической записи (без схемы — строка, открытая меткой времени, или строка с меткой и словом уровня); зелёный — строки из последнего авто-дочитывания.
- **Файл строки** (во вкладке несколько файлов): колонка слева от текста — полоса цвета файла на всю высоту строки и имя файла (полный путь — в подсказке). Имя, которое помещается в колонку, пишется целиком; длинное сокращается до различающей части (`…eu…` / `…us…` для `payment-service-prod-eu-1.log` / `payment-service-prod-us-1.log`), а у строки, занимающей несколько линий (Word Wrap), пишется целиком на нескольких линиях. **Ширина колонки меняется мышью**: потяните её правую границу (тонкая линия между именем и текстом; курсор над ней меняется); двойной щелчок по границе возвращает ширину по умолчанию — по самому длинному имени, но не больше 16 символов. Ширина запоминается и общая для всех вкладок. У высокой развёрнутой строки имя держится у верха экрана, а полоса идёт через все её части — видно, чья строка. Текст всех файлов начинается и обрывается на одной вертикали.
  - `View → File Labels`: **Name** (по умолчанию) — полоса и метка; **Color Only** — только полоса; **Hidden** — ничего. Настройка общая для всех вкладок и панели Search.
  - **Легенда** над логом (Name и Color Only): чип на файл — цвет, имя и сколько строк файла во вкладке (с 100 000 — сокращённо: `120K`; точное число и путь — в подсказке). **Щелчок по чипу скрывает строки файла**, повторный — возвращает; `Ctrl`+щелчок оставляет только этот файл (повторный — все); последний видимый файл не скрывается. Скрытый чип приглушён и зачёркнут. Число на чипе — всегда число строк файла, от фильтров и скрытия оно не зависит, и чипы не меняют размер. Кнопка **Files** тулбара Filters горит, пока файл скрыт (щелчок — показать все); **Reset Filters of This Tab** и **Show in Full Log** обращаются с фильтром по файлу как с остальными фильтрами, сессии его хранят. Правый щелчок по чипу: **Go to Next / Previous Line of This File** (от выбранной строки; переход попадает в историю; на вкладке больше миллиона показанных строк строка ищется в фоне, ход — в строке статуса; строка, выбранная вами за это время, главнее), **Copy Path**, **Show in Folder**.
  - Индикатор кодировки в строке статуса у такой вкладки называет файл текущей строки.
- **Номера строк** — `View → Line Numbers` (по умолчанию выключены) показывает сразу за жёлобом номер строки в её файле — тот же, что принимает `Go to Line`. Под фильтром номера идут с пропусками; в слитой вкладке номера разных файлов идут вперемешку, чей номер — говорят полоса или метка рядом. У высокой развёрнутой строки номер держится у верха экрана. Номера не выделяются и не копируются вместе с текстом.
- **Переключатель переноса справа:**
  - `+N` — строка длиннее видимой области: скрыто N символов (с 10 000 — сокращённо: `12K`, `3.4M`; точное число — в подсказке). Щелчок по ней или `Пробел` на выбранной строке разворачивает строку переносом.
  - `−` и тонкая **рейка** под ним — строка развёрнута. `−` держится у верха экрана, пока строка его пересекает, а рейка идёт вниз на всю строку: щелчок по `−` или в любом месте рейки сворачивает строку — даже из середины гигантской. После сворачивания строка остаётся на экране (у его верха, если начиналась выше). Щелчок засчитывается по отпусканию без протяжки — выделение текста, дотянутое до края, ничего не сворачивает.
  - На большой (индексной) вкладке строки не переносятся: `+N` и `Пробел` выбирают строку и показывают её полный текст в панели **Entry Details**.
  - Переключатель нарочно приглушённый; наведите на него — будет подсказка.
- **Отметки на полосе прокрутки** — короткие штрихи на вертикальном скроллбаре показывают, где среди показанных строк ошибки (Error и Fatal, красные) и предупреждения (жёлтые) — в правой половине, закладки — посередине, совпадения запущенного поиска панели Search — слева (на вкладке, по которой он идёт). Отметка уровня стоит у первой строки записи — той, куда ведёт `F8`. Когда строка на экране, её отметка — внутри ползунка: перетащите ползунок к отметке, и это место окажется на экране. Отметки следуют за фильтрами, дочитыванием, перезагрузкой и добавлением файлов; на очень большом логе они появляются чуть позже загрузки — считаются в фоне.
- **Подсветка синтаксиса** — строки, числа, hex, URL, пути, GUID, таймстампы, парные скобки.
- **Перенос по словам (Word Wrap)** — кнопка на панели, `View → Word Wrap` или `Alt+Z` (значение по умолчанию — в **Settings → Appearance**).
- **Размер шрифта** — `Ctrl` + колесо мыши над логом, `Ctrl++` / `Ctrl+-` или `View → Larger Font / Smaller Font`; `Ctrl+0` возвращает размер по умолчанию. Размер запоминается.
- **Строка статуса** — текущая строка и число видимых строк; когда фильтры что-то скрыли — и сколько строк в документе всего (`Line 12 of 5 000 (filtered from 116 384)`).

## Выделение, копирование и действия по контексту

- **Протяжка** мышью выделяет текст; **двойной клик** — умный токен.
- **Двойной клик распознаёт:** строки в кавычках, таймстампы, URL, пути к файлам, hex-литералы, IP-адреса, имена файлов, числа, слова. Подряд идущие разделители выделяются группой; клик по пробелам выделяет только пробелы (без перескока на следующее слово).
- **Расширение выделения с клавиатуры:** `Shift+←/→` — на символ, `Ctrl+Shift+←/→` — на токен/блок.
- **Копировать** — `Ctrl+C`.
- **`Пробел`** (когда фокус в логе) — перенести / вернуть текущую строку, как `View → Wrap / Unwrap Current Line` и переключатель `+N` / `−`; клавишу можно переназначить в настройках.
- **Правый клик → контекстное меню:**
  - **Copy** — копировать выделение; **Copy Whole Line** — всю строку под курсором.
  - Если выделен короткий фрагмент в одной строке:
    - **Find “…”** — быстрый поиск с панели инструментов (прыжок к следующему совпадению).
    - **Find All “…”** — все строки с ним списком в панели **Search**.
    - **Show Only Lines with “…”** / **Hide Lines with “…”** — добавить правило Contains / Not contains и отфильтровать вкладку. Правило сужает то, что вкладка показывает сейчас: если панель Text Filters описывает фильтр этой вкладки (или оба пусты), правило добавляется в панель, как по Apply; если в панели другие, не применённые к вкладке правила, их не трогают — правило получает только фильтр вкладки.
    - **Highlight Lines with “…”** — добавить маркер в Row Highlighters и окрасить такие строки.
  - **Word Wrap (this line)** — для разворачиваемой строки.
  - **Open Link** — если выделен URL.
  - **Open File / Open Containing Folder** — если выделен путь к файлу.
  - **Use as Time Filter Start / End** — выделенный таймстамп, а без выделения — время строки под курсором.
  - **Add Bookmark / Remove Bookmark** и **Add Bookmark with Note… / Edit Bookmark Note…** — закладка на строке под курсором (см. «Закладки»).

## Фильтрация

- **Уровень лога** — цветные кнопки на панели (Fatal…Trace), меню `Filters` или `Alt+1…Alt+6`. Нажатая кнопка — «показывать только этот уровень»; можно нажать несколько; если не нажата ни одна, видны все уровни. **Show All Levels** (`Alt+0`) отжимает все.
- **Reset Filters of This Tab** — меню `Filters` или `Ctrl+Shift+R`: разом снимает фильтры уровня, времени и текста с активной вкладки.
- **Show in Full Log** — меню `View`, контекстное меню строки или `Ctrl+Shift+L`: чтобы увидеть, что происходило *вокруг* строки отфильтрованной вкладки, фильтры уровня, времени и текста вкладки приостанавливаются (маркеры Row Highlighters остаются). Выбранная строка остаётся выбранной на том же месте экрана; если строка не выбрана, на месте остаётся верхняя строка экрана. Плашка над логом говорит, что фильтры приостановлены. **Return to Filtered View** (кнопка на плашке или та же команда ещё раз) возвращает ровно те же фильтры: если выбранная сейчас строка их проходит, она остаётся на месте; если нет (вы перешли на строку контекста) — снова выбирается строка, с которой уходили, на её прежнем месте экрана, а `Alt+←` вернёт к ближайшей видимой у строки контекста. Правка любого фильтра во время показа (кнопки уровней, Apply / Reset в Text Filters и Time Filter, таймлайн, **Restore Filters**) его заканчивает: действует новый фильтр, приостановленные отбрасываются; **Reset Filters of This Tab** тоже их отбрасывает. Состояние у каждой вкладки своё; сохранение сессии, закрытие вкладки и выход сохраняют приостановленные фильтры — вкладка вернётся отфильтрованной. После перехода к закладке, скрытой фильтром (панель Bookmarks), Show in Full Log выбирает саму строку закладки.
- **Диапазон времени** — панель *Time Range Filter*: задайте From/To и Apply. Поля заполнены диапазоном времени лога активной вкладки (с секундами и миллисекундами), а панель показывает этот диапазон и включён ли фильтр. **Whole Log** возвращает в поля весь диапазон. Граница, оставленная на краю лога, остаётся открытой — строки, дописанные в растущий лог, продолжают показываться. Если From позже To, ничего не применяется, и панель объясняет почему. Время строки можно подставить сюда из её контекстного меню.
- **Как читается время строки.** Метка без часового пояса считается локальным временем этого компьютера. Явный пояс учитывается: `Z`, `+02:00`, `+0200`, `+02` вплотную к времени, а также `+02:00`, `+0200`, `UTC`, `GMT` через один пробел (например, `2026-09-20 10:00:00 +0200`). Поэтому `10:00:00Z` и `12:00:00+02:00` — один и тот же момент, и файлы из разных поясов сливаются в одной вкладке правильно. Дробная часть секунд любой длины усекается до миллисекунд (`.1` — 100 мс, `.123456` — 123 мс). Распознаются `2026-11-18 13:55:36` (и с `T`), `2026/11/18 13:55:36` (nginx error) и `18/Nov/2026:13:55:36 +0000` (access-лог nginx / Apache) — в любом месте строки; `18/11/2026 13:55:36`, `11/18/2026 13:55:36`, `18.11.2026 13:55:36` и вид syslog `Nov 18 13:55:36` (и `Nov  8 …`) — только в самом начале строки. Если метка стоит в начале строки, берётся она. Месяцы — английские сокращения, регистр любой. У метки syslog нет года: она получает последний год, в котором этот день не позже следующего дня после изменения файла, поэтому файл, идущий через Новый год, читается верно, а строки, дописанные после Нового года, получают новый год. Время без даты — `13:55:40.016 [main] …` (Logback) и `[13:55:36 INF] …` (Serilog console), только в начале строки или сразу за `[` в начале — получает дату от конца файла: последняя такая строка — дата изменения файла (та, при которой её время ближе всего к времени изменения: строка `23:59:58`, записанная на диск в `00:00:03`, остаётся во вчерашнем дне), а к началу файла дата уменьшается на сутки каждый раз, когда время идёт назад больше чем на час (ровно час назад — перевод часов, а не полночь). Строки, дописанные к открытому файлу, продолжают уже показанные: после полуночи — следующий день. Пауза в логе дольше суток не видна — у строки нет ничего, кроме времени. Время в середине строки (`took 00:01:23`) меткой не считается. Фильтр по времени, таймлайн и панель деталей показывают моменты в локальном времени; текст строки не меняется.
- Панель **Text Filters** — скрывает строки, не подходящие под её правила (Include/Exclude, AND/OR, регистр и regex для каждого правила, опционально привязка к полю). Действует на **активную вкладку** кнопками **Apply** / **Reset**. Чтобы *найти* строки, ничего не скрывая, — панель **Search**, см. раздел **[Text Filters и Search](#text-filters-и-search)** ниже.

### Какое слово — какой уровень

Уровень записи задаёт **первое слева** слово из таблицы в строке, с которой запись начинается. Слово должно стоять отдельно (`[ERROR]`, `ERROR:`, `level=error` — да; `ERRORS`, `error_code` — нет), регистр не важен. Строки-продолжения (стек-трейс) получают уровень своей записи. Без схемы полей запись начинается со строки, которая открывается меткой времени: метка с самого начала строки (`2026-11-18 13:55:36 …`, `Nov 18 13:55:36 …`), сразу за `[` в начале (`[2026-11-18 13:55:36] …`) или метка access-лога в скобках после адреса клиента (`10.0.0.1 - - [18/Nov/2026:13:55:36 +0000] …`). Слово уровня для этого не нужно, поэтому access-логи, syslog и логи вида «метка сообщение» делятся на записи и без схемы. Запись начинает и строка, где есть и метка времени (где угодно), и такое слово. Строка с меткой в середине или под отступом — тело JSON, SQL, текст исключения — остаётся продолжением: момент и уровень у неё от записи, а не свои.

| Уровень | Слова |
|---|---|
| **Fatal** | `FATAL`, `CRITICAL`, `CRIT`, `SEVERE`, `EMERG`, `FTL` |
| **Error** | `ERROR`, `ERR` |
| **Warn** | `WARN`, `WARNING`, `WRN` |
| **Info** | `INFO`, `INF`, `NOTICE` |
| **Debug** | `DEBUG`, `DBG` |
| **Trace** | `TRACE`, `VERBOSE`, `VRB` |

По этому уровню работают кнопки уровней, цвет строки, переходы `F7` / `F8`, счётчики в Statistics; сканер каталога считает Fatal, Error и Warn по записям этого уровня; те же слова принимает блок **Level** в схеме полей. Цветом в тексте выделяется только слово, написанное заглавными. Слова `ALERT`, `PANIC`, `FAIL`, `FINE`, `FINER`, `FINEST`, `CONFIG` и однобуквенные уровни (`E`, `W` в logcat) уровнем не считаются: это обычные слова сообщений, а уровень задаёт первое слева слово таблицы. По той же причине имя компонента перед уровнем, совпавшее со словом таблицы (`[notice-worker] ERROR …`), даст уровень этого слова.

## Text Filters и Search

С текстом работают две панели, и отличаются они тем, **что происходит с логом**:

| | **Text Filters** | **Search** |
|---|---|---|
| Что делает | **скрывает** строки, которые не подходят | **перечисляет** подходящие строки; лог остаётся полным |
| Главная кнопка | **▶ Apply** (или `Enter` в правиле) | **▶ Search** (или `Enter` в правиле) |
| Отмена | **⟲ Reset** — вкладка снова показывает все строки | **✕ Clear** — список результатов пустеет |
| Где результат | в самом логе | в списке внутри панели Search; клик прыгает к строке в логе |
| Область | активная вкладка; у каждой вкладки свой фильтр | видимые строки активной вкладки |

Правила в обеих панелях одинаковые, и панели можно использовать вместе: сузить лог фильтром, потом искать в том, что осталось. Галочка **Highlight** в каждой панели дополнительно подсвечивает найденный текст в логе. После Reset / Clear правила остаются в панели — их можно применить снова.

### Правила

Каждое правило — одна карточка:

- **Contains / Not contains** — строка должна (Include) или не должна (Exclude) содержать текст.
- **AND / OR** — как правило связано с предыдущим (у первого правила связи нет).
- **Поле** — по умолчанию `(entire row)` — искать по всей строке; можно ограничить колонкой схемы Log Fields вкладки. Правило с колонкой ищет в этом поле при любом показе полей и решает за всю **запись**: поле берётся из первой строки записи, остальные её строки (стек-трейс, продолжение с отступом) следуют за ней — `Thread contains main` оставляет стек-трейсы записей `main`, правило **Exclude** прячет их вместе с записью. Правила по всей строке по-прежнему действуют построчно. Если выбранной колонки нет в схеме вкладки (например, после смены схемы или у вкладки нет схемы), правило не участвует, и карточка об этом сообщает — оно не ищет молча по всей строке; вернётся колонка — вернётся и привязка.
- **⚙ (шестерёнка)** — доп-опции правила: **Case sensitive** (учёт регистра) и **Regular expression**.
- **Образец цвета** — левый клик выбирает цвет подсветки совпадений правила, правый клик включает/выключает подсветку этого правила. Цвет автоматически подбирается контрастным к теме, но его можно переопределить.

### Как комбинируются правила (AND / OR)

Правила соединяются булевой логикой, одинаково в обеих панелях:

- **AND** («и») — строка должна удовлетворять **обоим** соседним правилам сразу. Пример: `Contains "Timeout"` **AND** `Contains "Disk"` — только строки, где есть *и* «Timeout», *и* «Disk».
- **OR** («или») — строке достаточно удовлетворять **хотя бы одному** правилу. Пример: `Contains "Timeout"` **OR** `Contains "Disk"` — все строки с «Timeout» **плюс** все строки с «Disk».
- Приоритет: **AND связывает сильнее OR**, то есть `A AND B OR C` читается как `(A AND B) OR C`.
- **Not contains** удобно комбинировать через AND: `Contains "error"` **AND** `Not contains "timeout"` — ошибки, кроме таймаутов.
- Новое правило связывается через **AND** в Text Filters (сузить) и через **OR** в Search (найти и это тоже). Связь всегда можно поменять вручную.

> Если несколько правил дают пустой результат — почти всегда причина в том, что они соединены **AND**, а искомые тексты находятся в **разных** строках (пересечения нет). Переключите связь на **OR**, чтобы увидеть объединение.

### Панель Search

В панели рядом и запрос, и результаты. Снизу окна (по умолчанию) или в отдельном окне правила слева, результаты справа; если пристыковать панель сбоку, где она узкая, результаты уходят под правила.

- Поиск охватывает **все видимые строки** активной вкладки, включая конец больших файлов; фильтры уровня, времени и текста вкладки по-прежнему ограничивают область поиска. Большие индексные логи просматриваются в фоне без загрузки всего текста в память. Во время поиска список показывает прогресс, после завершения — число совпадений.
- Клик по результату (или переход по списку стрелками) прыгает к этой строке в логе; фокус остаётся в списке.
- Результаты живут вместе с активной вкладкой: строки, дописанные в растущий лог, проверяются по мере поступления и добавляются в список — весь файл заново не просматривается; строку, которую ещё дописывали, проверят снова, когда она завершится. Изменения самого видимого набора — фильтры уровня, времени или текста, перезагруженный файл — запускают поиск заново. При смене вкладки поиск идёт по новой вкладке. Пока панель скрыта, такой полный поиск ждёт её появления.
- **Find All** отправляет сюда одно слово: кнопка **All** рядом с полем поиска на панели инструментов (`Ctrl+Shift+F`) или пункт **Find All “…”** в контекстном меню лога заменяет правила одним правилом `Contains` и ищет. `Ctrl+Shift+F` при пустом поле поиска просто открывает панель с курсором в первом правиле.

### Регулярные выражения

Галочка **Regular expression** трактует текст правила как **регекс в стиле Perl/PCRE**, а не как шаблон с подстановочными знаками командной строки:

- `*` — повтор предыдущего символа, а **не** «любые символы». Чтобы задать «любые символы», пишите `.*`.
- `.` — любой один символ; `\d` — цифра; `\d+` — одна или несколько цифр.
- Классы работают для **любого алфавита**: `\w` — буква, цифра или `_` (в том числе кириллица — `пользовател\w+`), `\b` — граница слова (`\bошибка\b`), `\s` — любой пробел; без учёта регистра `ОШИБКА` находит `ошибка`. `\d` принимает и не-латинские цифры (например, арабо-индийскую `٣`); буквы с диакритикой (`é`) — тоже буквы, `\W` их не находит. Те же правила — в поле быстрого поиска, Row Highlighters и фильтре сканера каталога по содержимому.
- Правило срабатывает, если выражение найдено **где угодно** в строке (якорь не нужен).
- Примеры: `entry number \d+` найдёт «entry number 42»; `Log entry number .*` найдёт любую такую запись; `(WARN|ERROR)` — строки с любым из двух уровней.
- **Неверное выражение** подсвечивается: поле обводится красным, под ним появляется текст ошибки с позицией. Пока выражение неверно, правило не участвует ни в фильтре, ни в поиске.

### Профили

Комбобокс **Profile** + кнопка **⋯** сохраняют наборы правил под именами (**Save**, **Save as new…**, **Rename…**, **Delete**). У Text Filters и Search профили свои. При переключении профиля с несохранёнными правками программа спросит, сохранить ли их.

## Подсветка строк (Row Highlighters)

- Панель *Row Highlighters* — недеструктивно красит строки целиком по совпадению с паттерном (строки **не** скрываются). Apply/Reset действуют на активную вкладку.

## Схемы полей (Log Fields)

- **Схема у каждой вкладки своя.** Список схем, переключатель **Show in the log** (**Whole line** / **Selected fields**) и выбор колонок панели *Log Fields* относятся к активной вкладке: смена схемы у одной вкладки не трогает колонки и фильтры по полям соседних, а при переключении вкладок панель показывает схему той, что открыта. Новая вкладка получает последнюю выбранную схему (с выбором показа и колонками). Прежнее поведение «одна схема на всё окно» — одним действием **Apply Schema to All Tabs** (меню **⋯** панели *Log Fields* или меню **View**): схема, выбор показа и колонки активной вкладки ставятся всем вкладкам. Сессия, `Ctrl+Shift+T` и память файла помнят схему вкладки.
- **Схема у каждого файла слитой вкладки.** У вкладки из нескольких файлов под списком схем есть строка **Applies to**: **All files** или один из файлов вкладки. Выберите файл — список схем показывает и меняет схему только этого файла: лог приложения и access-лог nginx читаются в одной вкладке каждый своей схемой (у файла JSON Lines или logfmt поля всегда из его ключей). Колонки вкладки — объединение колонок схем её файлов по имени; строка файла, у схемы которого нет ни одной показанной колонки, показывается исходной строкой, а правило фильтра по колонке, которой нет у схемы файла строки, на этой строке не срабатывает. Если у файлов разные схемы, при **All files** список показывает **(mixed)**; схема, выбранная для **All files**, ставится всем файлам вкладки. Смена схемы файл не перечитывает никогда: метки, уровни и границы записей даёт *формат строк* файла (ниже), а не схема. «Show in the log» и выбор колонок — общие для вкладки. Объединение вкладок и переход вкладки на индексный режим сохраняют схему каждого файла. Сессия, `last-session.json` и `Ctrl+Shift+T` помнят схему каждого файла; память файла помнит схему файла слитой вкладки: файл, добавленный во вкладку, получает свою схему, открытый отдельно — она становится схемой вкладки.
- **Схема подбирается сама при открытии.** Когда у новой вкладки появились первые строки, программа в фоне (файл не перечитывается, открытие не ждёт) выбирает схему: та, что вы сами выбирали в панели для файла с таким именем (имя без хвоста ротации, цифры не важны: `app-2026-11-26.log.3` и `app-2026-11-27.log` — одно имя), если она разбирает хотя бы половину строк; иначе лучшая схема каталога, которая строкам подходит; иначе схема по умолчанию (последняя выбранная), если разбирает хотя бы половину; иначе — без схемы. Подобранная схема помечена **auto** в списке, строка статуса пишет «Schema: Logback / Log4j (auto)». Сохранённое состояние файла (память файла, сессия, `Ctrl+Shift+T`) и ваш выбор — в том числе **(none)** — не оспариваются; выбор в панели запоминается для имени файла (до 200 имён). Список схем показывает, какую долю строк вкладки разбирает каждая, подходящие — первыми; под списком — «Parsed 99.6% of 2300 record lines · 3 did not match». **⋯ → Detect for This Tab** подбирает заново. Выключается в `Settings → General` («Pick a field schema automatically when a log is opened»).
- **У файла JSON Lines или logfmt** вместо списка схем панель показывает «JSON Lines · keys» и ключи начала файла галочками: отмеченный ключ — поле (колонка), снятый — нет; **Add Key…** добавляет ключ, которого нет в начале файла. Файл при этом не перечитывается.
- **Схема — шаблон строки.** Схема записывается одной строкой, которая выглядит как строка лога: `{Timestamp:time} [{Thread}] {Level:level} {Logger:word} - {Message}`. Текст вне фигурных скобок стоит как в строке (пробелы в шаблоне — один или несколько пробелов или табуляций в строке), `{Имя:вид}` — поле. У поля один вопрос — где оно кончается, и вид поля отвечает на него:

| Вид | Где кончается поле |
| --- | --- |
| `time`, `level`, `int`, `num`, `hex`, `uuid`, `ip`, `path`, `quoted` | там, где кончается его форма: метка времени любой формы, которую читает программа, слово уровня, число, …, строка в кавычках (значение — без кавычек, `\"` раскодируется) |
| `of(a\|b\|c)` | на одном из перечисленных значений (значения могут содержать пробелы, берётся самое длинное) |
| `word` | на пробеле или раньше — на следующем тексте шаблона |
| `text` (по умолчанию), `greedy` | на том, что стоит в шаблоне следом: тексте или поле с формой; `greedy` — на последнем вхождении |
| `padded` | на промежутке из двух и более пробелов |
| `width(N)`, `words(N)` | через N знаков, через N слов |
| `rest` (по умолчанию в конце) | в конце строки |
| `/регекс/` | где кончается совпадение регулярного выражения (такая схема медленнее: поля во вкладке считаются в фоне) |

  `{? … ?}` — необязательный участок (берётся, только если сошёлся он сам и то, что за ним), `{_}` или поле без имени — разбирается, но колонкой не становится, `{{` и `}}` — сами скобки. Шаблон, в котором конец поля не определён (`{Component} {Message}` — за полем только пробел), не принимается: программа говорит словами, что выбрать — одно слово, N слов, ширину, промежуток или список значений. Строка, разобранная только до какого-то места, оставляет сошедшиеся поля, а остаток уходит в последнее поле `rest` (обычно `Message`).
- **Редактор схем** — `Tools → Field Schemas…` или **Edit…** (и **⋯ → Manage Schemas…**) в панели *Log Fields*: обычное окно, можно работать в программе, не закрывая его. Слева — ваши схемы с долей разобранных строк файла активной вкладки, кнопки **New ▾** (**Empty**, **From Sample Lines** — шаблон, выведенный из строк вкладки, **From Template…** — вставить шаблон, **Import Grok…** — Grok-выражение, `%{TIMESTAMP_ISO8601:time} %{LOGLEVEL:level} …`, переводится в шаблон) и **⋯** (удалить, импорт и экспорт файла, папка схем). Справа — **Name**, **Description** и **Template**: ошибка шаблона подчёркнута на месте и названа словами. Ниже — таблица строк вкладки (с текущей), разбитых на поля, — ровно то, что покажет вкладка: в заголовке колонки — сколько в ней разных значений (`Level · 6`), в подсказке — самые частые со счётчиками; сотня значений там, где ждали шесть, обычно значит неверную границу. **Did not match** — строки файла вкладки, которые схема не разобрала, с номером строки и причиной словами («expected “[” at character 25, found “restart marker”»). Под ней — доля на строках файла вкладки (начало файла и строки равномерно по нему): «In the file: Parsed 99.6% of 2300 record lines · 3 did not match»; считаются только строки, с которых начинается запись (продолжения — стек-трейс, traceback — промахом не считаются), строка, разобранная только до какого-то места, считается за половину; пересчёт — после каждой правки, слишком медленная схема так и отмечается, окно не подвисает. Кнопка **Find a Schema** открывает справа панель подбора (раздел ниже); **Edit in Editor** открывает вариант новой схемой. Сохранение одно: **Apply to Tab** — схема вкладке (файл не перечитывается), **Save** — в файл схемы, **Save As…** — копией под новым именем. `Ctrl+Z` / `Ctrl+Shift+Z` отменяют и повторяют правки имени, описания и шаблона; закрытие окна и переход к другой схеме с несохранёнными правками спрашивают. Если правка переименовала поле (`{Time:time}` стало `{When:time}`), а правила фильтров вкладок, панелей *Text Filters* и *Search* или их профили ссылаются на прежнее имя, редактор предлагает переименовать поле и там.
- **Правка на строке образца.** Дважды щёлкните ячейку таблицы образцов (или выберите её и нажмите `F2`), выделите часть значения и нажмите **Make Field** (`Ctrl+M`, есть и в контекстном меню): выделенное станет новым полем (`Field1`, имя можно поменять). Текст ячейки до выделения остаётся неизменным текстом шаблона (или прежним полем), после выделения — прежним полем. Где новое поле кончается, решают строки файла вкладки (до 2300) — по тем же свидетельствам, что у **From Sample Lines**: разделитель сразу за выделением (`]`, `:`), форма самого выделения (число, IP-адрес, время, UUID…), форма следом (слово уровня, время, IP), промежуток из пробелов, постоянная ширина колонки, одно и то же число слов или закрытый набор значений (выделенное плюс найденные на этом месте в других строках). Выбирается вариант, который разбирает больше строк, затем — у которого в новом поле меньше разных значений; **Other Variant** (`Ctrl+Shift+M`) ставит на его место следующий. Если в строках нет ничего, что говорит, где поле кончается, редактор так и пишет и делает поле списком из выделенного значения: строки с другими значениями останавливаются на нём и попадают в **Did not match** — добавьте их через **Add Value…**. Правый щелчок по заголовку колонки (или по ячейке, или `Shift+F10`) — меню колонки: **Ends at** — все способы закончить поле с итогом на образцах («after 2 words — words(2): 14 values · 100%», «one of the listed values — of(6 values): 6 values · 100%»), текущий отмечен, невозможные — с причиной; **Rename…** (`Ctrl+R`), **Add Value…** (`Ctrl+Shift+A`, предлагает значения строк, остановившихся на этом поле), **Merge with Next** (`Ctrl+J`), **Hide** (`Ctrl+Shift+H` — участок по-прежнему разбирается, но колонкой не становится) и **Remove** (`Ctrl+Shift+D` — его текст уходит предыдущему полю). Каждая правка — один шаг `Ctrl+Z`; правка, которая сломала бы шаблон, не выполняется и объясняется словами, так что шаблон всегда остаётся рабочим.
- **Встроенные схемы** распространённых форматов есть в списке с первого запуска; схема подбирается сама при открытии лога (см. выше) или выбирается в списке панели *Log Fields*:

| Схема | Какую строку читает |
| --- | --- |
| Logback / Log4j | `2026-11-18 13:55:36.123 [main] INFO  com.example.App - Started` |
| Spring Boot | `2026-11-18T13:55:36.130Z  INFO 34786 --- [main] o.s.b.App : Started` |
| nginx / Apache access (combined) | `203.0.113.42 - - [18/Nov/2026:13:55:36 +0000] "GET / HTTP/1.1" 200 64 "-" "curl/8.5.0"` (и формат common) |
| nginx error | `2026/11/18 13:55:36 [error] 1234#1234: *99 open() failed` |
| Syslog | `Nov 18 13:55:36 web01 sshd[2231]: Accepted publickey` и `2026-11-18T13:55:38+0100 web01 systemd[1]: Starting nginx` (journalctl) |
| Serilog (console) | `[13:55:36 INF] Starting web host` |
| Serilog (file, with date) | `2026-11-18 13:55:36.123 +01:00 [INF] Starting web host` |
| Python logging | `2026-11-18 13:55:36,123 - myapp.db - INFO - Connected` |
| Python logging (basicConfig) | `WARNING:root:Watch out!` |

  Стек-трейсы и traceback Python остаются внутри своей записи. Встроенные схемы — обычные файлы в каталоге `patterns` рядом с настройками; их можно править, переименовывать и удалять, как свои: изменённую программа не перезапишет, удалённая не вернётся, а свою схему с тем же именем файла или тем же названием оставит как есть. Новая версия DendroLog обновляет только те встроенные схемы, которые вы не меняли. Чтобы вернуть удалённые встроенные схемы, удалите в этом каталоге файл `.builtin-schemas` и перезапустите программу.
- **Схемы прежних версий** (до этой версии схема была цепочкой блоков) переводятся в шаблоны один раз, при первом запуске: файл схемы остаётся под тем же именем, с тем же описанием и своими ключами, а прежний вариант кладётся в папку `patterns/converted-from-v3/` — ничего не удаляется. Нетронутые встроенные схемы прежней версии заменяются новыми шаблонами (две схемы Syslog — одной), изменённые вами — переводятся, как свои. Схема, сохранённая в сессии, памяти файла и `last-session.json`, читается тем же переводом: вкладка получает те же поля. Свои пресеты прежнего редактора переносятся в список схем. Имена колонок не меняются — правила фильтров по ним работают как прежде. Перевод может отличаться от прежнего разбора на строках, которые схема не описывает (прежний движок искал следующую опору, пропуская текст; шаблон останавливается и отдаёт остаток в `Message`).
- **Формат строк: обычный текст, JSON Lines, logfmt.** Как читаются строки файла — метки времени, уровни и где начинается запись — свойство файла, которое определяется при открытии (как кодировка), а не схемы. Строка статуса показывает его рядом с кодировкой: **JSON Lines (auto)**, **logfmt (auto)**, **Plain text (auto)**.
  - **JSON Lines** (каждая строка — JSON-объект: pino, Bunyan, Serilog CLEF, structlog, zap, ECS) и **logfmt** (пары `ключ=значение`: logrus, Go slog, Loki, Prometheus) — если так выглядит большинство первых строк файла. Время, уровень и сообщение берутся из ключей в любом порядке (`ts`, `time`, `timestamp`, `@timestamp`, `@t`, `t`; `level`, `lvl`, `severity`, `loglevel`, `levelname`, `log.level`, `@l`; `msg`, `message`, `@m`, `@mt`, `event`; и те же ключи в другом регистре). Время — строка (как в строке лога) или число — эпоха в секундах, миллисекундах, микро- или наносекундах (единица по величине числа); уровень — слово или число (0–7 — syslog, 10–60 — pino / Bunyan). Поля такого файла — `Timestamp`, `Level`, `Message` и ключи, которые есть у большинства первых строк, — при любой схеме вкладки; значения показываются раскодированными (`\"` → `"`, `\u0430` → `а`), фильтр по колонке ищет в раскодированном, поиск по всей строке — в тексте как в файле. Строка, которая не начинается с `{` или с пары `ключ=значение` (стек-трейс, строка с отступом), продолжает запись над ней. В **Entry Details** — раздел **Keys**: все ключи верхнего уровня строки с раскодированными значениями; `⧉` копирует их парами «ключ, табуляция, значение».
  - **Plain text** — запись начинает строка с меткой времени в начале (или с меткой и словом уровня). В файле почти без меток, где большинство строк начинается словом уровня (`WARNING:root:…`, `[INFO] …`), запись начинает и такая строка — traceback Python остаётся в своей записи; в логе с метками строка вроде `ERROR: detail` посреди записи её не рвёт.
  - Файл, в котором меньше 20 строк (только что начатый лог, `stdin`), читается как обычный текст — **Plain text (auto, few lines)**; формат решается, когда строк становится 20, и если это JSON Lines или logfmt, файл один раз перечитывается.
  - Щелчок по индикатору — выбор **Plain text**, **JSON Lines** или **logfmt**, **Keys…** — свои ключи времени, уровня и сообщения (через запятую, первый найденный в строке главнее; `log.level` находит и вложенный `{"log":{"level":…}}`), единица эпохи и шкала числовых уровней (Python: 10 — debug … 50 — critical), или **Detect automatically**. Выбор, который читает строки иначе, перечитывает файл; текущая строка остаётся на своём месте экрана, закладки и история переходов находят свои строки. Выбор помнят память файла, сессии и `Ctrl+Shift+T`; решение автоматики принимается заново каждый раз.
  - *Directory Scanner* считает уровни и записи файлов JSON и logfmt тем же правилом.
  - Схемы «JSON Lines» и «logfmt» прежних версий больше не нужны: нетронутая встроенная копия удаляется, изменённая вами остаётся и читает всю строку как `Message`.
- У схемы может быть **описание** (Description в редакторе): оно показывается подсказкой у схемы в списке редактора и панели *Log Fields* и сохраняется в файле схемы. Правка одного описания не считается изменением встроенной схемы — новая версия может заменить его текст; правка шаблона или названия — считается. Ключи файла схемы, которых DendroLog не знает, при сохранении сохраняются.
- Фильтр времени, таймлайн и слияние нескольких файлов берут момент из самой строки по правилам из раздела «Как читается время строки» выше — со схемой и без неё. Время без даты (Serilog console `[13:55:36 INF]`, Logback `13:55:40.016`) получает дату по правилу оттуда же.
- **Show in the log: Selected fields** показывает у каждой строки только выбранные поля; выбор учитывается в **Save View As**. Этот выбор — только про показ: правила фильтра по полю и **Entry Details** работают при любом выборе. Смена схемы вкладки мгновенна на логе любого размера: поля считаются из текста строки, когда они нужны, файл заново не читается.

## Подбор схемы (варианты и AI)

`Tools → Find a Schema…` (или **⋯ → Find a Schema…** в панели *Log Fields*) открывает окно с вариантами разбиения строк активной вкладки на поля, у каждого — доля разобранных строк, начинающих запись, на одних и тех же строках файла вкладки (начало и строки, разбросанные по нему):

- **Your schemas** — до трёх схем из вашего списка, лучше всех разбирающих эти строки.
- **From the structure of the lines** — шаблоны строки, выведенные из самих строк, без сети: полный и осторожный (останавливается на первом поле, конец которого не установлен). Заметка говорит, где текст остался в `Message`, потому что устойчивой границы нет.
- **AI** — **Ask AI…** просит шаблон у Claude (см. ниже).

Справа — шаблон (`{Timestamp:time} [{Thread}] {Level:level} {Message}`: литеральный текст стоит как в строке, `{Имя:вид}` — поле), доля разобранных строк, таблица настоящих строк вкладки, разбитых на поля (в заголовке колонки — сколько в ней разных значений: неожиданная сотня значений обычно значит неверную границу), и не подошедшие строки с причиной словами. **Use for This Tab** ставит выбранную схему или шаблон вкладке, для которой открыто окно, и показывает его поля; файл заново не читается. **Save to My Schemas…** добавляет шаблон в ваш список схем (файлом в папке `patterns`).

### Подсказки AI: что и когда уходит в сеть

Подсказки AI по умолчанию **выключены**. Чтобы ими пользоваться, откройте `Settings → AI`, включите **Suggest field schemas with AI (Claude)** и введите ключ Claude API (console.anthropic.com); запросы оплачиваются по этому ключу, несколько центов за запрос на модели по умолчанию. Ключ не хранится в `DendroLog.ini`, сессиях и журналах: на Windows он зашифрован для вашей учётной записи Windows (DPAPI) в папке настроек; на Linux — файл, доступный только вашему пользователю, в `~/.local/share/…` (не зашифрован — страница настроек об этом говорит); в portable-режиме на Linux не сохраняется вовсе. Переменная окружения `ANTHROPIC_API_KEY` главнее. **Remove Key** удаляет сохранённый ключ.

Ничего не отправляется при открытии лога и в фоне — только по нажатию **Ask AI…** и только после окна подтверждения, где показано ровно то, что уйдёт: хост (`api.anthropic.com`), модель, число строк и символов и полный текст запроса. По умолчанию включены **Mask values** (цифры становятся `0`, длинные hex-значения и UUID — `a`, адреса почты — `user@example.com`, IP — адресами документационных диапазонов; метки времени и слова уровней остаются) и **Cut lines to 300 characters**. Маскировка уменьшает то, что уходит с компьютера, но не убирает всё: слова, имена и пути внутри строк уходят как показаны. Имя файла, его папка, имя пользователя и компьютера не отправляются. Уходит до 40 строк, начинающих запись, и неизменные инструкции (грамматика шаблона и примеры; их показывает **Instructions sent with every request**). Галочки «больше не спрашивать» нет.

Ответ проверяется до показа: шаблон, который не компилируется или разбирает меньше 90 % строк, начинающих запись, ведёт к одному уточняющему запросу — снова только после того же окна подтверждения, теперь с прежним шаблоном, проблемой и до 10 не подошедших строк; слишком длинный шаблон, больше 32 полей или слишком медленный на этих строках отклоняется с причиной. Шаблон с `/регулярным выражением/` помечается как более медленный: поля такой схемы во вкладке считаются в фоне — строки сначала видны целиком, а выбранные колонки появляются, как только посчитаны (прокрутка и выбор строки при этом не ждут; Entry Details пишет «Computing fields…»), и фильтр по полю с такой схемой всегда идёт в фоне. Ничего не применяется само: подсказка появляется в списке, как остальные варианты.

## Быстрый поиск по строке (панель инструментов)

- Поле поиска на панели инструментов — это разовый поиск по тексту (не путать с панелью **Text Filters** выше). `Ctrl+F` ставит фокус в него (и показывает скрытый тулбар Find; сочетания поиска ниже тоже работают и возвращают его); `Enter` / `F3` — следующее совпадение, `Shift+F3` — предыдущее (то же — кнопки-стрелки рядом). Три переключателя рядом с полем уточняют его (см. ниже). Поиск начинается от выделенной строки (если её скрыл фильтр — от её места; без выделения — с начала, а для `Shift+F3` — с конца) и переходит через край. Найденная строка разворачивается и становится выделенной, термин подсвечивается; Follow tail выключается, чтобы растущий лог не увёл вид обратно к хвосту. Поиск идёт в фоне, и окно не замирает даже на огромном логе без совпадений: у долгого поиска в строке статуса виден прогресс, `Esc` в поле поиска его отменяет, а ненайденный термин окрашивает поле в красный и отмечается в строке статуса.
- Переключатели: **Aa** (`Alt+C`) — учитывать регистр; подчёркнутое **ab** (`Alt+W`) — слово целиком: совпадение не должно примыкать к букве, цифре или `_` ни слева, ни справа, поэтому `error` пропустит `errors` и `my_error`, но найдёт `[error]`; **.\*** (`Alt+R`) — регулярное выражение, тот же синтаксис, что в Text Filters (см. «Регулярные выражения» выше: найдено где угодно в строке). «Слово целиком» работает и с регексом: `\d+` найдёт число, не прилипшее к буквам. **Невалидное выражение** обводит поле красным, подсказка поля и строка статуса говорят, что не так и в какой позиции, и поиск не запускается, пока выражение не исправлено. Переключатели запоминаются между запусками.
- **Последние запросы:** стрелка вниз в поле (или кнопка-стрелка у его правого края) открывает список 20 последних запросов, свежий сверху; выбор пункта запускает его снова. Запрос попадает в список, когда поиск действительно запущен (`Enter`, `F3`, `Shift+F3`, кнопки-стрелки, **All**), а не по мере набора; запоминается только текст, переключатели остаются как есть. Пункт **Clear search history** внизу списка очищает его.
- Чтобы увидеть сразу все строки с термином, нажмите **All** рядом с полем (`Ctrl+Shift+F`): панель **Search** перечислит их, ничего не скрывая (см. выше). Регистр, «слово целиком» и регекс переносятся: панель получает одно правило с тем же учётом регистра, а запрос-регекс или «слово целиком» становится правилом **Regular expression** (слово целиком — текст, обёрнутый проверками границ слова). В панели Search можно задать и несколько правил сразу.

## Переход к строке и ко времени

- `Ctrl+G` или `View → Go to Line / Time…` открывает одно поле ввода. Цифры — это **номер строки файла**, тот же, что показывает Entry Details. Всё остальное — **время**: `10:02`, `10:02:03.250`, дата `2026-03-05` или оба — `2026-03-05 10:02`. Время без даты берёт дату выделенной строки, а если ничего не выделено — дату начала лога. После времени можно указать зону (`Z`, `+03:00`, `UTC`); без неё время локальное, как и в самом логе.
- Подпись под полем показывает, куда приведёт переход, ещё до нажатия **Go**. Если строка скрыта фильтрами, переход идёт к ближайшей показанной — следующей за её местом, а если такой нет, к последней. Номер за концом файла ведёт к его последней строке. Время ведёт к первой показанной строке не раньше него; время позже всего лога — к последней строке с меткой.
- Во вкладке с несколькими файлами номер строки относится к одному файлу: его выбирает список **Line of file**, изначально это файл выделенной строки. На переход ко времени он не влияет.
- Строка становится выделенной, поэтому остаётся на месте, когда после этого меняются фильтры.
- Большой файл, открытый один, показан в порядке файла; если метки времени в нём идут не по порядку, переход ко времени там приблизителен.

## История переходов

- `Alt+←` (`View → Navigate Back`) возвращает туда, откуда вы перешли; `Alt+→` (`View → Navigate Forward`) — снова вперёд, как в браузере. То же делают боковые кнопки мыши «назад» / «вперёд» над логом.
- Считается любой переход к строке: Go to, щелчок по таймлайну или в Statistics, результат Search, быстрый поиск (`F3`), следующая ошибка (`F8` / `F7`), закладки (`F2`, панель Bookmarks) и плашка **↓ N new lines**. В историю попадает выделенная строка, с которой ушли (если ничего не выделено — первая строка экрана), и строка, куда пришли. Щелчки, стрелки и прокрутка — не переходы и не записываются.
- Серия переходов одного вида без движения между ними — `F3`, `F3`, `F3` по совпадениям, `F8` за `F8`, листание результатов Search стрелками — один шаг: одно `Alt+←` возвращает туда, где вы читали до неё. Новый переход после возврата отбрасывает «вперёд», как в браузере. История хранит последние 100 мест.
- Возврат выделяет строку и выключает Follow tail, как любой переход, и в историю ничего не добавляет. Место, скрытое фильтрами, ведёт к ближайшей показанной строке. Места переживают дочитывание, перезагрузку того же содержимого и переход в режим больших файлов; место, чьей строки больше нет (файл переписан или удалён), пропускается.
- У каждой вкладки своя история; она не сохраняется и исчезает при закрытии вкладки.

## Дельта времени

- **`View → Time Delta`** (по умолчанию выключено) добавляет колонку сразу за номерами строк: время от предыдущей показанной строки с меткой — `+12 ms`, `+1.234 s`, `+2 m 03 s`, `+5 h 07 m`, `+3 d 04 h`. Считаются только строки на экране, по индексу строк, поэтому на очень большом логе колонка ничего не стоит.
- «Предыдущая» — предыдущая строка, которую показывает вкладка: под фильтром дельта считается между показанными строками. Дельта стоит у первой показанной строки записи; остальные строки многострочной записи (стек-трейса) живут её временем и остаются пустыми, как и строка без метки. Строка раньше той, что над ней (слитая вкладка, большой лог в порядке файла), получает отрицательную дельту: `−1 h 01 m`.
- **«Нулевая» строка:** правый щелчок по строке → **Set as Time Zero** или выделить её и нажать `Ctrl+Shift+D` (`View → Set / Clear Time Zero`). Пока «нулевая» задана, колонка показывает время от неё у каждой записи (строки до неё — со знаком `−`); у самой «нулевой» — `= 0`. Та же команда на «нулевой» — или **Clear Time Zero** в контекстном меню любой строки — снимает её. Строка без метки «нулевой» быть не может. «Нулевая» переживает фильтры (скрытая фильтром тоже считается), дочитывание, перезагрузку и переход на режим больших файлов; у каждой вкладки своя, на диск она не сохраняется.
- **Entry Details** всегда показывает под заголовком обе дельты выбранной строки: `Δ previous` и `Δ time zero` (от минуты — с точным числом миллисекунд). То же — в подсказке над ячейкой дельты.

## Следующая и предыдущая ошибка

- `F8` / `Shift+F8` (`View → Next Error` / `Previous Error`) переходят от выделенной строки к ближайшей записи уровня **Error** или **Fatal**; `F7` / `Shift+F7` — то же для **Warn**. Если ничего не выделено, поиск идёт с начала (назад — с конца).
- Многострочная запись (стек-трейс) считается один раз: переход ведёт к её первой показанной строке, а не по каждой строке трейса.
- Учитываются только показанные во вкладке строки: скрытое фильтрами пропускается.
- За последней такой строкой переход продолжается с другого края вкладки — об этом сообщает строка статуса. Она же говорит, что таких строк нет вовсе или что выделенная строка — единственная.
- Строка становится выделенной, Follow tail выключается — как при переходе Go to.
- На очень большом логе поиск идёт в фоне (уровень берётся из индекса строк, текст не читается), и окно не замирает; у долгого поиска в строке статуса виден прогресс, повторное нажатие начинает его заново. Если показанные строки изменились, пока он шёл (закончился фильтр, файл перечитан), строка статуса просит нажать клавишу ещё раз.

## Закладки

- `Ctrl+F2` (`View → Add / Remove Bookmark`) ставит закладку на выделенную строку или снимает её; то же делает контекстное меню строки, оно же может спросить заметку. У строки с закладкой в левом поле — лента-флажок.
- `F2` / `Shift+F2` (`View → Next Bookmark` / `Previous Bookmark`) переходят от выделенной строки к следующей / предыдущей закладке среди показанных строк; за последней переход продолжается с другого края вкладки, как у `F8`. Закладки на строках, скрытых фильтрами, пропускаются.
- Закладка принадлежит одной физической строке, а не записи целиком: закладка на строке стек-трейса остаётся на этой строке.
- Панель **Bookmarks** (`Ctrl+F11`) — закладки текущей вкладки: файл и номер строки, начало текста строки и заметка, которую можно править прямо там. Щелчок по файлу и номеру — переход к закладке, ✕ снимает её, **Clear All** снимает все закладки вкладки (после подтверждения: закладки хранятся между запусками).
- Закладка на строке, скрытой фильтрами, помечена **hidden by filter**; щелчок ведёт к ближайшей показанной строке. Сняли фильтр — отметка в поле вернулась.
- Закладки переживают дочитывание хвоста, полную перезагрузку файла и переход растущего файла в режим больших файлов. Если файл переписан и строки больше нет или у неё другой текст, закладка остаётся в панели с текстом и заметкой, помеченная **line not found**, и не переезжает на чужую строку. Если поставить закладку на эту строку заново, прежняя закладка привяжется к ней и сохранит заметку. Пока файл читается заново, закладка помечена **line not loaded**. Закладка находится заново по номеру и тексту строки — и тогда, когда строку в этот момент скрывает фильтр.
- **В панели Search** у строки выдачи — лента закладки её строки во вкладке, в контекстном меню строки выдачи — те же пункты закладок; `Ctrl+F2`, когда фокус в выдаче, ставит закладку на строку вкладки, которой соответствует выбранный результат. Закладка — вкладки: она сразу видна в логе и в панели Bookmarks, а поставленная или снятая там сразу видна в выдаче.
- При объединении вкладок закладки присоединяемой вкладки вместе с заметками переходят во вкладку-приёмник.
- Закладки сохраняются между запусками — см. «Память файла».

## Память файла

- Открытый снова файл получает прежние **закладки** с заметками, **маркеры** (Row Highlighters) и **позицию**: выбранную строку на том же месте экрана (или слежение за хвостом, если оно было включено), а также авто-дочитывание и выбранную вручную кодировку. Неважно, как файл открыт: из командной строки, перетаскиванием, из недавних, из Directory Scanner.
- **Схема полей** файла, который был во вкладке один, возвращается сразу (с выбором **Show in the log** и колонками), если такая схема есть в каталоге; если её там больше нет, вкладка получает схему по умолчанию, а строка состояния сообщает «Remembered schema … is not in the catalogue».
- **Фильтры** (уровни, время, Text Filters) сами не применяются: над логом появляется плашка «This file was filtered when you last closed it», кнопка **Restore Filters** возвращает их одним щелчком, ✕ прячет плашку до закрытия вкладки (фильтры при этом не забываются).
- Файл, добавленный во вкладку вторым, получает только свои закладки. Если во вкладке несколько файлов, у каждого запоминаются его закладки, а позиция и фильтры — только у файла, который был во вкладке один.
- Память пишется при закрытии вкладки, при выходе и через 2 секунды после правки закладки или заметки — аварийное завершение теряет не больше этих 2 секунд.
- **Файл переписан** (ротация, перезапись) — он открывается чистым, прежние закладки видны в панели Bookmarks серыми (**line not found**) с текстом и заметкой и в лог не попадают; строка состояния говорит об этом. Память прежнего содержимого не теряется: **перенесённый или переименованный** файл (`app.log` → `app.log.1`, лог, распакованный в другую папку) находит свою память по содержимому. Копия файла получает копию памяти.
- Поток stdin и вывод команды не запоминаются.
- **Где лежит:** папка `memory` в каталоге настроек — рядом с программой в portable-режиме, иначе `%LOCALAPPDATA%\DendroLog` (Windows) или `~/.config/DendroLog` (Linux). По файлу на лог, не больше 200 файлов: давно не открывавшиеся вытесняются, файлы с закладками — нет. **В них есть пути к логам и фрагменты их строк** (до 200 символов строки с закладкой) — учтите это, если каталог настроек уезжает вместе с программой на съёмном носителе.
- **Выключить и очистить:** **Settings → General → File memory** — флажок «Remember bookmarks, markers, position and filters of each file» (выключен — память не читается и не пишется) и кнопка **Clear Memory…**. Открытые вкладки после очистки запишут своё состояние снова при закрытии.
- Два окна (`--new-instance`) на один файл не затирают закладки друг друга: побеждает последняя запись, но закладки, поставленные в другом окне, добавляются, а снятые в этом окне не возвращаются.

## Сессии

Сессия — снимок всего окна в файле `*.dlsession`: его можно открыть позже, на другой машине или передать коллеге вместе с логами.

- **File → Save Session As…** сохраняет все вкладки: файлы каждой вкладки (слитая вкладка — все её файлы), фильтры (уровни, время, Text Filters), маркеры (Row Highlighters), закладки с заметками, выбранную строку и её место на экране (или слежение за хвостом), авто-дочитывание, выбранную вручную кодировку, а также активную вкладку, схему полей (имя и саму схему), флажок извлечения полей и выбор колонок.
- **Не сохраняется:** поток stdin и вывод команды (вкладка с ними не попадает в сессию — команда из сессии не запускается, а у слитой вкладки «stdin + файл» сохраняется файл), раскладка панелей (она хранится в настройках), содержимое панелей Text Filters и Row Highlighters (их профили и так переживают перезапуск). Файл сессии — снимок: сам он не обновляется, чтобы записать изменения, сохраните сессию ещё раз.
- **File → Open Session…** открывает вкладки сессии в сохранённом порядке **рядом с уже открытыми** (их сессия не закрывает) и делает активной сохранённую активную вкладку. Сессию можно открыть и как файл: передать `*.dlsession` в командной строке (`DendroLog.exe incident.dlsession`, в том числе в уже открытое окно) или перетащить в окно. Расширение в системе не регистрируется.
- **Схема полей** — у каждой вкладки своя (с выбором **Show in the log** и выбором колонок). Если в каталоге схем есть схема с тем же определением (имя не важно), вкладка получает её; иначе схема добавляется в каталог под именем с пометкой «(from session)» — одна запись на одинаковые схемы. Уже открытые вкладки свою схему не меняют. Вкладки сессии, сохранённой версией 0.6 (схема одна на окно), получают схему сессии; сессия без схемы оставляет новым вкладкам схему по умолчанию. Версия 0.6, открывшая сессию новой версии, ставит всем вкладкам схему активной вкладки.
- **Закладки и память файла.** Фильтры, маркеры и позицию вкладка берёт из сессии, а не из памяти файла; закладки объединяются: к закладкам сессии добавляются более новые из памяти файла, у совпавших по строке заметка — из сессии.
- **Перенос на другую машину или в другую папку.** Рядом с абсолютным путём каждого файла сессия хранит путь относительно себя. Положите файл сессии рядом с логами (или в общую с ними папку) — после переноса папки целиком файлы найдутся по относительному пути. Если файл есть и по прежнему пути, и рядом с сессией, берётся прежний. Сессия открывается и на другой ОС: сохранённая на Windows (`C:\…`, сетевой путь `\\server\share\…`) — на Linux, и наоборот; путь другой ОС не открывается, файл ищется только рядом с сессией, а если его там нет — пропускается и называется в отчёте своим путём с той машины.
- **Отчёт о восстановлении.** Открытие ничего не спрашивает. Если файл не найден ни по одному пути, он пропускается (его закладки ждут файл); если файл изменился с момента сохранения (ротация, перезапись), он открывается чистым, закладки в панели серые (**line not found**), позиция не ставится. Об этом и о файлах, найденных рядом с сессией, сообщает ссылка в строке состояния — она открывает окно **Session Report**: вкладка, файл, что случилось. Для ненайденного файла кнопка **Locate File…** позволяет указать, где он теперь: принимается только тот же файл (его начало и сохранённая часть совпадают), закладки переходят на него. Пропавший и не указанный файл остаётся в сессии при повторном сохранении.
- Сессия, сохранённая более новой версией DendroLog, не открывается, и файл не трогается.

### Прошлый сеанс и закрытые вкладки

- **Прошлый сеанс.** При выходе DendroLog запоминает вкладки окна так же, как **Save Session As…** (файл `last-session.json` в каталоге настроек). Окно, закрытое без вкладок, прошлый сеанс не затирает; закрытое с вкладками — заменяет его, даже если прошлый не восстанавливали. Сеанс запоминается только при обычном выходе (закрытие окна, `Ctrl+Q`); после аварийного завершения остаётся предыдущий.
- **Восстановление при запуске** — флажок **Settings → General → Sessions → Restore the tabs of the previous session on startup**, по умолчанию выключен. Включён — при запуске открываются вкладки прошлого сеанса, затем файлы из командной строки. Выключен — стартовый экран показывает ссылку **Restore previous session**, пока сеанс не восстановлен. Восстановление ничего не спрашивает: о ненайденных и изменённых файлах сообщает ссылка в строке состояния на тот же **Session Report**.
- **Несколько окон.** Прошлый сеанс принадлежит основному окну. Окно, открытое с `--new-instance` или читающее поток (`program | DendroLog -`), его не восстанавливает и не перезаписывает и основным не становится: чужих файлов не принимает, а обычный запуск рядом с ним открывает основное окно. Файлы, переданные в уже открытое основное окно (повторный запуск, двойной щелчок по файлу), открываются новыми вкладками и восстановления не запускают. Основное окно закрыто — основным становится следующее обычное.
- **Вернуть закрытую вкладку** — `Ctrl+Shift+T` (**File → Reopen Closed Tab**): вкладка возвращается на прежнее место в ряду с файлами, фильтрами, маркерами, закладками, выбранной строкой, выбором кодировки и своей схемой полей. Помнятся последние 10 закрытых вкладок, до выхода из программы. Вкладка потока stdin, вкладка команды, пустая вкладка и вкладка, слитая с другой, не запоминаются. Если файл за это время переписан или удалён, об этом сообщает строка состояния, как при открытии сессии.

## Дочитывание файлов

- **Reload** — `F5` или кнопка на панели: дочитывает добавленное в конец содержимое. Сжатый файл (`.gz`) авто-дочитывание не перечитывает; `F5` распаковывает его заново, если архив изменился, а если архив пропал — распакованные строки остаются.
- **Авто-дочитывание** — тогл рядом с Reload, `File → Auto-reload This Tab` или `Ctrl+Shift+F5` (правый клик по Reload тоже работает); для каждой вкладки своё. Вкладки с авто-дочитыванием отмечены значком. Интервал — в **Settings → General**.
- **Follow tail** — тогл со стрелкой вниз или `Shift+F5`: держит в виду самые новые строки; его выключает прокрутка вверх и любой переход к строке (Go to, найденная строка поиска, результат в панели Search, таймлайн, статистика, следующая ошибка).
- **↓ N new lines** — пока вы читаете выше хвоста с выключенным Follow tail, строки, дописанные ниже экрана, считаются на плашке у нижнего края представления. Считаются только строки, которые показывают фильтры вкладки; больше 99 999 число сокращается (`120K`, `3.4M`), точное — в подсказке. Щелчок по плашке или `Alt+End` (`View → Go to New Lines`) ведёт к первой новой строке: она становится выделенной, Follow tail остаётся выключенным, а строки, попавшие на экран, из счёта уходят — повторное нажатие листает дальше. Плашка исчезает, когда вы дошли до низа или включили Follow tail. Смена фильтра или перезагрузка переписанного файла начинает счёт заново; у каждой вкладки он свой.

## Кодировки

- **Определяется сама.** UTF-8, Windows-1251, IBM866 (cp866), KOI8-R и Windows-1252 — у каждого файла своя кодировка, в том числе во вкладке с несколькими файлами. Пока в файле только ASCII, решать нечего — текст одинаков в любой кодировке. Решает первый байт за пределами ASCII, где бы он ни оказался — хоть на третьем гигабайте, хоть в дописанном хвосте: если байты похожи на UTF-8 — UTF-8, иначе запасная кодировка (между кириллическими Windows-1251, IBM866 и KOI8-R выбор по самим байтам). Файл с BOM UTF-8 читается как UTF-8. Если не-ASCII байтов пока мало (одно-два слова), решение **предварительное**: оно перепроверяется, когда байтов прибавится, и, если поменялось, файл перечитывается без потери места в логе.
- **Индикатор** в правой части строки статуса показывает кодировку файла текущей строки и откуда она: `Windows-1251 (auto)`, `… (auto, provisional)` — предварительно, `UTF-8 (BOM)`, `KOI8-R (manual)` — выбрана вручную, `ASCII (auto)` — пока только ASCII. Во вкладке с несколькими файлами — кодировка файла выбранной строки.
- **Выбрать вручную** — щелчок по индикатору: UTF-8, Windows-1251, IBM866, KOI8-R, Windows-1252. Файл показывается в новой кодировке сразу — большой файл не переиндексируется; текущая строка, выделение и место на экране сохраняются, поиск, фильтры, закладки и история переходов работают с новым текстом. Выбор переживает дочитывание, перезагрузку переписанного файла и объединение вкладок и запоминается в памяти файла (см. «Память файла»); `--encoding` в командной строке главнее запомненного. **Detect automatically** снимает выбор и возвращает решение автоматики. Выбрать можно и пока файл только ASCII.
- **Запасная кодировка** — **Settings → General → Non-UTF-8 files**: что брать для файла не в UTF-8. По умолчанию — по языку системы (кириллица — Windows-1251, иначе Windows-1252). Смена действует на новые файлы и на открытые, у которых решение ещё не окончательное; уже решённые и выбранные вручную не меняются.
- **Командная строка** — `DendroLog --encoding cp1251 app.log` открывает файлы этой кодировкой (как выбор вручную); `program | DendroLog --encoding cp866 -` — то же для потока. Имена: `utf-8`, `windows-1251`/`cp1251`, `ibm866`/`cp866`, `koi8-r`, `windows-1252`/`cp1252`. Неизвестное имя — сообщение в окне, файлы открываются с автоопределением. Через уже открытое окно (второй запуск) аргумент тоже действует.
- **Save View As** всегда пишет UTF-8: во вкладке могут быть файлы в разных кодировках, а UTF-8 сохраняет всё без потерь.
- **Directory Scanner** ищет по содержимому той же кодировкой, что и вкладка: по BOM (UTF-8, UTF-16, UTF-32), иначе по тому же правилу автоопределения с той же запасной кодировкой. Запрос, который находит строку во вкладке, находит и файл в сканере. Смена запасной кодировки перепроверяет только файлы, которые от неё зависят.
- **Ограничения.** UTF-16 и UTF-32 узнаются только по BOM и читаются целиком в обычном режиме: большой такой файл не индексируется, выбрать для него кодировку нельзя, а во вкладке с другими файлами он не открывается — откройте его отдельной вкладкой. Блок «мусора» в начале файла (сотни байтов не-ASCII, не похожих на текст) может дать неверное окончательное решение — поправьте выбором вручную.

## Цветные логи (ANSI-последовательности)

- **Коды скрыты.** Программы с цветной консолью (`docker logs`, `kubectl logs`, вкладка вывода команды, Spring Boot, Serilog console, pino-pretty, npm) пишут в текст escape-коды вида `ESC[31m`. DendroLog снимает их при чтении строки — во всех вкладках и в Directory Scanner, — поэтому поиск, Find All, Text Filters, Row Highlighters, схемы полей, Entry Details, копирование и **Save View As** видят обычный текст: `ERROR foo` находит строку, где красным только `ERROR`, а слово уровня в цвете и метка времени за кодом цвета узнаются как обычно. Сам файл не меняется.
- **Цвета видны.** Цвета кодов (16 и 256 цветов, 24-битные, жирный, курсив, подчёркивание, приглушённый, инверсия) рисуются в логе оттенками, читаемыми в светлой и тёмной теме; цвет, почти неразличимый на своём фоне, заменяется цветом текста. Обычная раскраска чисел, строк и путей заполняет части, которые программа не раскрасила. Каждая строка начинается без цвета: цвет, включённый в одной строке, на следующую не переходит.
- **Выключить** — **View → ANSI Colors** или **Settings → Appearance → Show ANSI colors**. Коды скрыты в любом случае.
- Цвета показываются для текста строки, а не для выбранных колонок схемы полей. Закладки и позиции на строках с escape-кодами, сохранённые DendroLog 0.6, будут «не найдены».

## Directory Scanner

- Кнопка с папкой выбирает каталог и сканирует его на файлы с нужными расширениями; в дереве видны число записей, диапазон времени, счётчики W/E/F и размер. Подкаталоги раскрываются по требованию.
- **Ротированные логи тоже в дереве**: кроме `app.log` видны `app.log.1`, `app.log.10`, `app.log-20260101`, `app.log.2026-01-01` и `app-2026-01-01.log` — расширение из настроек, за которым идёт только номер или дата ротации (цифры, разделённые `.`, `-` или `_`). Резервные копии и файлы редакторов (`app.log.bak`, `app.log.swp`, `app.log~`) в дерево не попадают. Ротированные файлы встают сразу за основным, по номеру: `app.log`, `app.log.1`, `app.log.2`, `app.log.10`. Фильтр «Log files» диалога **Open** знает только обычные расширения: чтобы открыть ротированный файл из диалога, выберите там «All files» — или откройте его из сканера.
- **Архив `.zip`, `.tar`, `.tar.gz` или `.tgz`** показывается здесь извлечённым: подпись — имя архива, **←** — назад к прежней папке (подробнее — в разделе об открытии файлов).
- **Сжатые логи тоже в дереве**: `app.log.gz`, `app.log.1.gz`, `app.log-20260101.gz` — имя, которое без `.gz` попало бы в дерево. Счётчики, From / To и фильтр по содержимому читают их с распаковкой на лету, ничего не записывая на диск, и дают те же цифры и находки, что несжатый файл; столбец **Size** показывает размер на диске, прогресс фильтра по содержимому идёт по сжатым байтам. Повреждённый или оборванный архив — «Parse Failed». Изменившийся `.gz` перечитывается целиком (дозаписи у архива не бывает).
- **Записи считаются так же, как в открытой вкладке**: запись начинается так же, как во вкладке без схемы (см. «Какое слово — какой уровень»), а строки после неё (стек-трейс, многострочное сообщение) принадлежат ей. Счётчики W/E/F считают такие записи, диапазон From / To берётся из их меток. Схема полей на счёт не влияет: сканер считает, как вкладка без извлечения полей. Файл в UTF-16 узнаётся по BOM, а растущий лог, последняя строка которого ещё дописывалась, после её завершения пересчитывается без лишней записи.
- Имена сортируются **без учёта регистра** и «естественно»: `log2` идёт перед `log10`. Клик по заголовку столбца меняет сортировку (имя — по возрастанию, числовые столбцы — сначала по убыванию).
- **Кнопка ⟳ — обновление.** Клик перечитывает каталог, но не весь: заново разбираются только новые и изменившиеся файлы, а дописанный в хвост лог дочитывается с прошлой позиции (если файл не переписали целиком). Удалённые файлы уходят из дерева.
- **Правый клик по ⟳** выбирает режим обновления:
  - **Refresh manually** (вручную, по умолчанию) — дерево не меняется само, но при изменениях на диске кнопка подсвечивается: «есть что подтянуть».
  - **Refresh automatically** (автоматически) — изменения приезжают сами; период задаётся тут же в пункте «Auto-refresh interval…». Пока панель скрыта, обновление откладывается до её показа.
  - **Refresh off** (отключено) — ничего не отслеживается; кнопка по-прежнему обновляет по требованию.
- **⚙ раскрывает фильтры.** Фильтр по содержимому читает файлы в фоне; прогресс считается **в байтах**, поэтому полоса отражает реальный ход даже когда один файл на порядки больше остальных. Повторное применение того же запроса берёт результат из кэша (мгновенно), а включённый фильтр по датам сужает круг читаемых файлов. Кодировка файла определяется так же, как во вкладке (см. «Кодировки»): кириллица в Windows-1251, IBM866, KOI8-R и текст в UTF-16 находятся, с учётом и без учёта регистра, подстрокой и регулярным выражением; дописанный или ротированный файл перепроверяется своей кодировкой.

## Панели и компоновка

- Панели включаются из меню **View** или клавишами `Ctrl+F1`, `Ctrl+F3…F11` (Text Filters `Ctrl+F1`, Time Filter `F3`, Log Fields `F4`, Row Highlighters `F5`, Timeline `F6`, Search `F7`, Entry Details `F8`, Statistics `F9`, Directory Scanner `F10`, Bookmarks `F11`; `Ctrl+F2` — клавиша закладок). Положение панелей запоминается между сессиями; `View → Reset Panel Layout` возвращает раскладку по умолчанию.
- Длинные списки в панелях Text Filters, Row Highlighters и Log Fields прокручиваются, а не растягивают панель за край окна.
- Панель **Search** показывает правила и результаты рядом, если пристыкована снизу, и друг под другом — если сбоку.

## Настройки и тема

- **Tools → Settings** (`Ctrl+,`):
  - **General** — расширения для сканера, интервал авто-дочитывания, большие файлы, запасная кодировка, память файла (см. «Память файла»), сессии, подбор схемы полей при открытии лога.
  - **Appearance** — тема окна, моноширинный шрифт и размер (живой предпросмотр), перенос по словам по умолчанию, цвета ANSI.
  - **Colors** — цвета уровней, синтаксиса, выделения и интерфейса.
  - **AI** — подсказки схем полей нейросетью: включены или нет (по умолчанию выключены), модель, ключ API (см. *Подбор схемы*).
  - **Shortcuts** — переназначение любой команды; кнопка ⊗ в поле снимает сочетание, **Restore Defaults** возвращает стандартные. Сочетание, отданное двум командам, подсвечивается красным, и OK не принимает настройки, пока конфликт не устранён. Если новая версия даёт команде сочетание по умолчанию, которое вы уже отдали другой команде, клавиша остаётся у вашей команды, а у новой поле пустое, и под ним сказано почему («Default Alt+Left is assigned to “Go to line or time…”»). Кнопка ↺ у поля, отличного от умолчания, возвращает умолчание только этой команде; её подсказка говорит, что станет с командой, державшей клавишу: она получит своё сочетание по умолчанию или, если и его кто-то держит, останется без сочетания.
- **Тема** (**Settings → Appearance → Theme**): **Same as system** — окно следует светлой или тёмной теме системы и переключается вместе с ней (так по умолчанию); **Light** и **Dark** — всегда светлая или тёмная, что бы ни было выбрано в системе. Выбор применяется сразу, без перезапуска, и запоминается. Цвета вкладки **Colors** — один набор на обе темы.
