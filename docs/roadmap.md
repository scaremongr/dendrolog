# План разработки DendroLog

Составлен 17 ноября 2026 для версии `0.4.0` по итогам двух ревизий (`docs/review-2026-09-20.md` и ревизии 17 ноября). Заменяет раздел 9 сентябрьской ревизии: её этапы 1–2 выполнены, остаток этапа 3 вошёл сюда как релиз 0.5.

Этот файл — единственное место, где записано, что делать дальше. Статус задачи меняется в том же PR, что и сама работа. Что уже сделано — в `CHANGELOG.md`, как устроен код — в `CLAUDE.md`.

## Как читать

- **Объём:** S — одна короткая сессия; M — одна сессия, один PR; L — сначала сессия проектирования, затем 2–4 PR.
- **Зона** — какие модули задача трогает. По ней видно, какие задачи можно вести параллельно (см. «Процесс»).
- **Статус:** `ждёт`, `в работе`, `готово`.
- Каждый релиз — одна тема плюс 2–4 задачи из UX-трека. Тема отвечает на вопрос «зачем обновляться», UX-задачи — «почему приятнее».

Что известно про P-1 (проверено 17 ноября в облачном контейнере, Ubuntu 24.04):

- CMake 3.28, GCC 13 и Ninja есть, Qt нет.
- Qt из apt — 6.4.2, проект с ним не собирается: `QRegularExpression::matchView` (`filterruleset.cpp`, `textmatchhighlighter.cpp`) появился в 6.5.
- `download.qt.io` закрыт сетевой политикой окружения, поэтому путь CI (`install-qt-action`) здесь не работает.
- conda-forge доступен, там есть `qt6-main` 6.8.4. Установка не проверена.
- Варианты: поставить Qt 6.8 из conda-forge либо разрешить окружению `download.qt.io`. Понижать минимальную версию Qt до 6.4 не стоит: от 6.5 зависит и слежение за темой ОС.

## Процесс

### Где живёт состояние

Только в репозитории: этот файл (что дальше), `CHANGELOG.md` (что сделано), `CLAUDE.md` (как устроен код и правила), описание PR (решения по задаче). Сессия агента ничего не помнит и не должна.

### Одна задача — одна сессия — одна ветка — один PR

Новая сессия на каждую задачу: контекст не засорён чужой работой, ревью получается независимым, а параллельные задачи не мешают друг другу. Долгая сессия на несколько задач теряет детали при сжатии контекста.

### Виды сессий

| Вид | Когда | Результат |
| --- | --- | --- |
| Проектирование | Задачи L | `docs/design/<ID>.md`: решение, отвергнутые варианты, разбиение на PR, план проверок. Кода нет |
| Реализация | Каждая задача или её часть | PR с кодом, тестами, документацией и статусом в этом файле |
| Ревью | Задачи, трогающие потоки, хранилище или `LogListView` | Отдельная сессия без контекста реализации: `/code-review high` по PR |
| Релиз | Закрыта тема релиза | Версия в `CMakeLists.txt`, раздел в `CHANGELOG.md`, сверка справки; тег ставит автор |
| Ревизия | После каждого релиза | Свежий взгляд на проект и обновление этого файла |

### Шаги сессии реализации

1. Прочитать `CLAUDE.md`, задачу здесь и, если есть, `docs/design/<ID>.md`.
2. Продуктовые вопросы — сразу и одним списком; дальше без остановок.
3. Сначала проверка: падающий offscreen-тест на критерий «Готово, когда».
4. Реализация. Логику, которой нужен `MainWindow`, выносить в контроллер без виджетов — как `SearchResultsController`.
5. Сборка и полный `ctest`.
6. `CHANGELOG.md`, обе справки, при необходимости `README.md` и карта модулей в `CLAUDE.md`, статус здесь.
7. `/code-review` по диффу, исправление найденного.
8. Ветка и PR — если об этом сказано в постановке задачи.
9. CI собирает Windows и Linux; автор берёт `DendroLog-dev-NN` из артефактов запуска, пробует руками и мержит.

### Где запускать

- **Локально на Windows** — задачи, где нужен живой интерфейс, Windows-специфика, замеры на больших файлах, скриншоты (Q-1, S-2).
- **В облаке** — всё остальное, после P-1. До P-1 облачная сессия не может собрать проект и годится для документов, планирования и ревью.

### Параллельность

Не больше двух сессий реализации одновременно и только с непересекающимися зонами. Не вести параллельно две задачи, трогающие `LogListView`, хранилище (`logstore`, оба бэкенда) или `mainwindow`. Конфликты в `CHANGELOG.md` и справке неизбежны и решаются при слиянии.

### Постановки задач

```text
Возьми задачу Q-2 из docs/roadmap.md и выполни по разделу «Процесс». В конце запушь ветку и открой PR.
```

```text
Спроектируй R-1 из docs/roadmap.md: только docs/design/R-1.md, без кода.
```

```text
Сделай /code-review high для PR <номер>. Реализацию не правь, только находки.
```

```text
Подготовь релиз 0.5.0 по разделу «Процесс».
```
