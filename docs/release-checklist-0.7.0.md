# Релиз 0.7.0: что решено без автора и что проверить руками

Подготовлено 27 ноября 2026 релизной сессией (исполнитель): версия, `CHANGELOG.md`,
справки, README и сценарий обновления с 0.6.0 в `tests/mainwindow_smoke`.
Релиз выпущен 27 ноября 2026: тег `v0.7.0` на коммите `3019219`
(«Release v0.7.0: версия, CHANGELOG, справки, обновление с 0.6.0»), файлы —
на странице релиза https://github.com/scaremongr/dendrolog/releases/tag/v0.7.0
(установщик и portable для Windows, AppImage для Linux). Тег поставил
конвейер Release по запуску планировщика; CI и Sanitizers по `3019219`
зелёные, локальный полный `ctest` — 39/39.

В релиз вошло всё, что пришло в `main` после `v0.6.0` (`a98b246`): F-17
целиком (поля по шаблону строки, подбор схемы при открытии, формат строк JSON
Lines / logfmt без схемы, редактор на шаблонах с правкой на строке, «Find a
Schema» с подсказчиком AI), F-2 (сжатые логи и архивы), F-3 (ANSI), F-4, F-5,
F-7, F-8, F-9, F-11, U-19, U-20, U-23, U-27 и исправления (S-13, S-14, S-15,
S-23, S-25, Q-25 и другие).

**Найдено при подготовке и исправлено в релизном коммите.** Вкладка
`last-session.json` или файла сессии 0.6.0 получала схему сеанса с
происхождением «по умолчанию» (`SessionState::topLevelFields`), и подбор схемы
при открытии мог заменить её другой схемой каталога. Схема сохранённого
состояния — выбор пользователя; теперь она `Origin::User`, как схема вкладки
снимка без ключа `origin`. Ловит сценарий «upgrade from 0.6.0» оконного смоука
и проверка в `document_state`.

## Решения, принятые без автора в 0.7

Формат: решение — почему — как изменить.

| Решение | Почему | Как изменить |
| --- | --- | --- |
| **Подбор схемы при открытии включён по умолчанию.** После первой порции строк новой вкладки, в фоне: схема, выбранная раньше для файла с таким именем (хвост ротации и цифры не важны), если разбирает ≥ 50 % строк; иначе лучшая «подходящая» из каталога; иначе схема по умолчанию при ≥ 50 %; иначе без схемы. Сохранённое состояние (память файла, сессия, `Ctrl+Shift+T`) и выбор пользователя, «(none)» включительно, не оспариваются | Цель F-17 — поля без настройки; файл не перечитывается, открытие не ждёт подбора | `[App] autoPickSchema` (Settings → General), пороги — `src/schemapick.h`, `docs/design/F-17.md` шаг 8 |
| **Выбор схемы в доке запоминается по имени файла** — `[SchemaByName] entries` в ini, до 200 имён | Чтобы `app-2026-11-27.log` получил ту же схему, что вчерашний | `SchemaPick::NameTable` (`src/schemapick.h`) |
| **Каталог схем переводится в шаблоны строки при первом запуске**: файл версии 3 → шаблон версии 4 под тем же именем, с описанием и неизвестными ключами; оригинал байт в байт — в `patterns/converted-from-v3/` (не перезаписывается: `_2`, …); непереводимый файл не трогается. Нетронутые встроенные — поставляемыми шаблонами по манифесту, изменённые — как свои. Схемы в сессиях, памяти файла, `last-session.json` и ini читаются тем же конвертером | Блочной модели в программе больше нет; ничего не удаляется, путь назад — оригиналы. 0.6.0 шаблонов не читает | `SchemaStore::migrateToTemplates`, `SchemaConverter` (`src/schemaconverter.h`) |
| **На строках, которые схема не описывает, перевод может разбирать иначе**: шаблон останавливается на первом несовпадении и отдаёт остаток последнему полю (прежний движок искал следующий якорь, пропуская текст) | Одна семантика разбора, линейная по длине строки | Правка шаблона в редакторе (Make Field, Ends at) |
| **Две встроенные syslog-схемы (ISO и RFC 3164) — одна «Syslog»**; выбранная прежняя следует за заменой | Один шаблон с видом `time` читает обе формы | `resources/patterns/syslog.json`, `BuiltinSchemas::kRetired` |
| **JSON Lines и logfmt — формат строк файла, а не схема.** Решается по первым строкам (до 200 непустых в 256 КБ; большинство — объект JSON или пары `key=value`); меньше 20 непустых строк — «не решён», читается как обычный текст, с 20 строк решается один раз и файл перечитывается. Сохраняется только выбор пользователя | Время, уровень и границы записей не должны зависеть от выбора схемы; смена схемы — O(1) | Индикатор формата в строке статуса; `LineFormatDetector` (`src/lineformat.h`) |
| **Лог без меток, где большинство строк начинается словом уровня, режется по слову уровня** (меток < 10 %, ведущее слово уровня ≥ 50 %) | Traceback Python остаётся в своей записи без схемы; в логе с метками `ERROR:` посреди записи её не рвёт | `LineFormat::levelStartsRecord`, `LineFormatDetector::decide` |
| **Схема не влияет на чтение**: строку, которую раньше началом записи делала только схема (метки и слова уровня в ней нет), запись больше не начинает | Чтение и поля разделены (инвариант 13 `CLAUDE.md`) | Формат строк файла; редкий случай — задачей, если появятся жалобы |
| **Схема с `/регексом/` считает поля в фоне**: строки сначала сырые, колонки появляются по готовности; фильтр по полю с такой схемой — всегда фоновый | Регекс может быть катастрофическим; GUI-поток не ждёт | `FieldExtractor::cost`, `FieldSource` |
| **Подсказчик AI выключен по умолчанию.** Модель `claude-opus-5-5`; запрос только по кнопке **Ask AI…** и после окна согласия с точным текстом; до 40 строк-кандидатов, значения маскируются (цифры, hex, UUID, почта, IP; метки и уровни целы), строки режутся до 300 символов — оба флажка включены по умолчанию; имя файла, папка, пользователь и компьютер не уходят; одно уточнение, если шаблон не компилируется или разбирает < 90 % строк | Отправка строк лога наружу — решение пользователя каждый раз | Settings → AI; `src/schemaproposal.h`, `src/aischemaclient.h` |
| **Ключ API не в ini.** Windows — DPAPI-файл `<configDir>/ai-key.dpapi`; Linux — файл 0600 в каталоге 0700 `~/.local/share/…/ai-key` **открытым текстом** (страница настроек об этом говорит); в portable-режиме на Linux не сохраняется; `ANTHROPIC_API_KEY` главнее | Без зависимости от libsecret / KWallet; portable-каталог переносят на флешке | `src/secretstore.h`; связка ключей ОС — отдельной задачей |
| **Цвета ANSI включены**, коды из текста сняты всегда (поиск, фильтры, поля, экспорт видят текст без кодов); файл на диске не меняется | Цветной вывод `docker logs` / `kubectl logs` — главный случай; без цвета коды всё равно мусор | View → ANSI Colors, Settings → Appearance (`[View] ansiColors`) |
| **Закладки и сохранённые позиции 0.6 на строках с ANSI-кодами — «не найдены»** | Отпечаток строки считается без кодов (R-1), а старый учитывал их; пересчитывать старые отпечатки не из чего | Поставить закладку заново |
| **Колонка дельты времени выключена**; «нулевая» строка на диск не пишется | Колонка нужна при разборе задержек, а не всегда | View → Time Delta (`[View] timeDelta`), `Ctrl+Shift+D` |
| **Номера строк выключены** | Лог — не исходник; ширина текста дороже | View → Line Numbers (`[View] lineNumbers`) |
| **Метка файла слитой вкладки — колонкой слева с именем** (режим Name), ширина авто до 16 символов, протяжка мышью запоминается для всех вкладок; правая плашка файла убрана | Текст всех файлов на одной вертикали; длинные имена не съедают ширину | View → File Labels (`[View] fileLabels`, `fileColumnChars`) |
| **Фильтр по файлу — щелчок по чипу легенды**; последний видимый файл скрыть нельзя; число на чипе — всегда строк файла | Чип как переключатель привычнее отдельного диалога; постоянные числа не прыгают | `src/filelegend.*` |
| **Время без даты** (`13:55:40.016`, `[13:55:36 INF]`) — только с позиции 0 или 1 за `[`; дата — от mtime файла назад, минус сутки на каждый шаг времени назад больше чем на час | Иначе такие логи не упорядочиваются и не попадают на таймлайн | `docs/design/F-11.md`, `LineClassifier` |
| **Сжатый `.gz` распаковывается во временную копию** в каталоге кэша (`<CacheLocation>/spool`), копия живёт, пока открыта вкладка; резерв свободного места 512 МБ; авто-обновление `.gz` не трогает, `F5` перераспаковывает изменённый; брошенное упавшим экземпляром убирается при следующем запуске | Индексному бэкенду нужен файл с произвольным доступом | `SourceUnpacker`, `SpoolDir` |
| **zip и tar открываются в Directory Scanner**, а не вкладкой: извлекаются только логи (по расширениям сканера и их `.gz`), опасные имена и ссылки пропускаются, имена zip без флага UTF-8 и не UTF-8 — как IBM866 (без локали) | Архив — набор файлов; извлекать всё ради одного лога дорого | `DirectoryScannerPanel::openArchive`, `ZipArchive`, `TarArchive` |
| **Вывод команды без shell по умолчанию** (одна программа, аргументы по пробелам, кавычки группируют); закрытие вкладки — SIGTERM группе, через 3 с SIGKILL (Windows — job-объект); вкладка команды не сохраняется ни в сессии, ни в памяти файла, ни в закрытых вкладках | Команда никогда не запускается сама | `CommandSpec`, `CommandSpooler` |
| **Новые сочетания по умолчанию: `Ctrl+Shift+D` (нулевая строка дельты), `Space` (перенос текущей строки, только в фокусе лога)**; сочетание, уже отданное пользователем другой команде, остаётся у неё, новая — без клавиши, Settings показывает уступленное умолчание с «↺» | Правило 0.6 «ваше сочетание остаётся вашим», теперь видимое (U-20) | `ShortcutManager` |
| **Правило по полю решается на записи** (по полям её первой строки, продолжения идут за записью); правило по колонке, которой нет в схеме вкладки, — нейтральное | Иначе `Thread contains main` прятал стек-трейсы записей `main` | `FilterRuleSet`, `FieldRecordCursor` |
| **Схема — у вкладки, у файла слитой вкладки может быть своя**; новая вкладка берёт последнюю выбранную; всем вкладкам сразу — только «Apply Schema to All Tabs». Сессии 0.6 дают всем вкладкам схему сеанса, 0.6 читает новые сессии со схемой активной вкладки | Соседние вкладки с разными форматами не мешают друг другу | `FieldSchemaController`, `docs/design/F-5.md` |
| **Экспорт CSV — с BOM UTF-8 и CRLF**, JSON Lines — без BOM; значения пишутся как есть (текст с `=` Excel может принять за формулу) | Excel без BOM читает CSV в кодировке Windows; экранировать формулы — значит менять данные | `ViewExport` (`src/viewexport.h`) |

## Ручная проверка на Windows (15–20 минут)

Только то, что offscreen-тесты не проверяют или что не запускалось на
настоящем дисплее. Логика покрыта тестами (`ctest`, 39 тестов, в том числе
оконный смоук `tests/mainwindow_smoke` со сценариями обновления с 0.5.0 и
0.6.0).

**Где взять сборку.** Страница релиза
https://github.com/scaremongr/dendrolog/releases/tag/v0.7.0 (после выпуска):
`DendroLog-0.7.0-setup.exe` и `DendroLog-0.7.0-win64-portable.zip`; до выпуска —
артефакты CI по релизному коммиту. Версия внутри — 0.7.0 (Help → About).

**Подготовка.** Установленная 0.6.0 с настройками, которыми пользовались: своя
схема полей (выбрана в доке Log Fields), закладка в каком-нибудь логе, сессия
(File → Save Session As…), своё сочетание клавиш. Логи:
`python scripts/generate_test_log.py --format jsonl` (JSON Lines),
`docker logs` или `npm` с цветом в файл (или `python -c "print('\x1b[31mERROR\x1b[0m boom')" > color.log`),
любой лог, сжатый в `.gz`, и `.zip` с двумя логами.

| # | Шаг | Ожидается |
| --- | --- | --- |

| 14 | `Space` в фокусе лога на длинной строке; `Space` в поле быстрого поиска | В логе строка разворачивается («−» и рейка), в поле — пробел |
